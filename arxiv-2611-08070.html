001Lesson 1 · The big claim~6 min

Can an AI read another AI's brain?

Imagine someone hands you a closed box and says: "Tell me what game this AI was trained to play — just by weighing the box." No test images, no running it, no hints. Only a huge list of numbers the network learned, called its weights.

A 2026 report by Takehi and colleagues claimed this is already possible. They called it weight-space programming: a general AI reading and editing another AI's weights as if they were text. Their headline examples were striking:

  • naming the game a small game-playing network was trained on,
  • fixing a failing control network by editing only 3.5% of its weights,
  • and improving a large language model, Qwen3.5-0.8B, on a math test from 7.9% to 48.1% by editing just 0.016% of its weights — about 131,072 out of 800 million numbers.

If true, that's powerful for checking AI. You could audit a model for hidden abilities by inspecting its wiring, not by designing test questions.

But there's a cheaper way to sound right. Many public datasets are famous. A network that takes a $32\times 32$ color image and outputs 10 numbers already looks like CIFAR-10, a well-known set of 10 everyday-object photos, before you read a single weight. A correct guess — "It's CIFAR-10!" — could come from memory, not from tracing how pixels flow to outputs.

The key distinction: Reading means following the wiring from inputs through middle layers to outputs. Remembering means spotting a familiar footprint — input size, output count, number formatting — and filling the rest from a memorized template.

This paper asks only the reading question, with a different model — Claude Opus 5.5 — on small image classifiers with about 123,000 to 127,000 parameters. Each session received every weight as plain text, rounded to three decimals, in a fresh chat with no tools, no code, no ability to run the network, and no dataset or class names. The audit then varied the dataset, the order of labels, and how well the network was trained, to see when a good answer survives and when it breaks.

Think of it like deciding if someone actually read a book or just guessed the cover. The lab below shows why the cover alone — the network's shape — is already a strong clue you have to beat.

Try the lab: change the fingerprint from $32\times 32$ with 10 outputs to other shapes. Watch how the most common public guess snaps to CIFAR-10 even with zero weights read, and notice what a careful reader would need to prove instead.

002Lesson 2 · How the tiny brain works~8 min

What's inside a tiny image classifier?

A tiny image classifier is like an assembly line. An image goes in one end as numbers, gets scrubbed and squeezed a few times, and comes out the other end as a short list of scores — one score for each possible answer. The audit's networks all follow the same line, so once you picture one, you picture them all.

It starts with a photo resized to 32 × 32 pixels in red, green and blue. Before the network even sees it, each color channel is standardized: subtract a fixed mean and divide by a fixed spread, so colors are centered around zero. That helps training but also hides clues — Claude was not told those means.

Then three identical blocks run in order. Each block does four things: a convolution with small 3 × 3 filters, a ReLU, a max-pool, and a batch-norm.

🔍

Filter & bias

A filter (or kernel) is 9 numbers in a 3×3 square. It slides over the image and adds up matches — big sum means “I see that edge.” A bias is one extra number added after. Model 1 uses 16 filters in block 1, then 32, then 64.

✂️

ReLU & pool

ReLU keeps positives, turns negatives to 0 — like “only shout if you are sure.” 2×2 max-pool keeps the loudest of each 2×2 patch and throws the rest away, which halves width and height: 32 → 16 → 8 → 4.

🧮

Batch-norm & logits

Batch-norm tidies numbers using a running mean (average) and running var (spread) saved during training. After the three blocks, a dense layer (78 to 175 units, with dropout 0.3 in training) mixes everything, then the last layer outputs logits — 2, 6 or 10 raw scores, one per class. Biggest logit wins.

Those details matter because the audit gave Claude everything as plain text: every filter, bias, and running mean/var rounded to 3 decimals. That is about 124,000 to 127,000 numbers per network. Training itself was ordinary PyTorch + Adam, learning rate 0.001, batch 128, up to 100 epochs.

The output size follows the dataset. CIFAR-10 has 10 classes (vehicles vs animals), KMNIST has 10 Japanese characters, Cats vs Dogs has 2, the fast-food set has 10 but only 3,000 photos total, and SAT-6 has 6 satellite land-cover classes (barren, building, grassland, road, trees, water) with 81,000 patches. The whole game is: from those numbers alone, can Claude tell which set the line was built for?

003Lesson 3 · Designing a fair test~7 min

How do you test an AI that claims to read weights?

Say someone claims they can tell what a network was trained to do just by reading its numbers. How do you check if they really followed the wiring, or just guessed the most famous answer that fits the shape?

This is the trap the audit had to build. Every network here comes in as plain text: nothing but layer formulas and thousands of numbers rounded to 3 decimals. No dataset name, no class names, no note about how it was standardized, which optimizer was used, or what augmentations were applied. The wording is kept identical for a given architecture — so a network that saw Japanese characters gets called an “RGB image” just like one that saw color photos. That way the words can’t leak the answer.

Each question also goes to a fresh Claude Opus 5.5 session with no memory, no tools, no code, and no ability to run the network, at the highest effort setting. The model gets one try to look and answer. Most conditions were run only once — the paper is clear this is exploratory, not a big statistical trial — and the scoring rules were written down beforehand: did it name the dataset exactly? Did it describe the image type right? Did it get classes right at the exact output number (“in position”) versus anywhere (“any position”)?

🏷️

1. Permute labels

Keep the same trained weights but move CIFAR-10 vehicles to outputs 2, 4, 5, and 7. Accuracy stays 82.37% vs 82.36% and the weight pattern stays — only the remembered index → name map breaks.

🔀

2. Shuffle weights

Scramble the numbers inside each array, keeping the same values and shapes. Accuracy falls to 7.78% — worse than guessing. Any real reader should now say “no structure.”

🍔

3. Familiar vs obscure

Same 32×32 size, different worlds: famous CIFAR-10 and KMNIST versus fast-food photos (3,000 images) and SAT-6 satellite patches (81,000 images, 6 classes). Shape alone can’t tell them apart — can reading?

🧱

4. Standard vs weird shape

Model 1 uses normal widths (16, 32, 64). The “Random” architecture uses odd widths (62, 68, 25) picked to have the same ~125k parameters but no size divisible by 8 or 10. Does a strange middle change the guess?

📈

5. High vs low accuracy

SAT-6 on Model 2 at 99.57% versus the same setup stopped after 3 updates at 36.01%. If accuracy helped, the near-perfect network should be easiest to name.

Together these are controls, not just extra tests. They let you ask: was a correct “CIFAR-10!” based on real number-crunching, or on “32×32 with 10 outputs usually means CIFAR-10”?

The key idea: a good test keeps the weights’ structure but changes what memory would predict. Label permutation does exactly that.

Try it yourself below — turn the traps on and off and watch what a memory-guesser says versus what a true wire-tracer would say. Pay attention to how accuracy and structure stay or break.

004Lesson 4 · What it got right~8 min

What the AI got right: local math at the edges

Imagine you cannot open a book, but you can weigh its cover. The weight of the cover won't tell you the plot, but it can tell you how many pages were added. The AI in this audit did something similar: it didn't follow the whole wiring from pixels to prediction, but it did good bookkeeping on the numbers sitting right at the entrance and exit.

Success 1 was counting training steps. One SAT-6 satellite network was stopped after just 3 updates. Claude looked at its batch-normalization numbers — the little tidy-up layer that keeps values centered. Two of those numbers matter here: weight (also called gamma) which usually stays near 1 early on, and running_var which tracks how spread-out values have been.

How 3 steps becomes readable
PyTorch's batch-norm has a default momentum of 0.1. Each step it does: $$ new\_running\_var = 0.9 \times old + 0.1 \times batch\_var $$
Starting near 1, after n steps the stored value is about 0.9ⁿ. After 3 steps that's 0.9³ = 0.729. The prompt listed running_var ≈ 0.729 and weight ≈ 1 — Claude turned that back into "about three Adam steps," which was correct. No middle-layer tracing needed.

Success 2 was spotting the vehicle/animal split in CIFAR-10. CIFAR-10 has 10 outputs where, in the standard order, {0,1,8,9} are vehicles (airplane, automobile, ship, truck) and {2,3,4,5,6,7} are animals. Claude looked only at the last layer: each of the 78 hidden units has 10 weights, one to each output. Are those 10 weights positive or negative?

Seven hidden units had exactly the same sign pattern: positive toward the four vehicle outputs and negative toward the six animal outputs (or the reverse — the key is they agree). The next most common pattern was shared by only 3 units. The paper also checked with PCA — a way to find the biggest overall trend in the table — and that first trend explained 27.7% of the variation and split the same two groups (28.5% on Model 2). Again, that's math on a list of numbers at the edge, not a trace through the middle.

The audit also tried a grayscale test on KMNIST (handwritten Japanese characters). The logic was clever: the input was described as RGB, but if the images are really gray copied three times, the three color channels get identical gradients during training, so their filters cannot drift far apart. PyTorch's starting range limits that drift to about 0.385, and both KMNIST nets stayed below it with maxima of 0.367 and 0.345.

Claude called those grayscale — reasonable, but not decisive. Why? The same check also passed on the fast-food color networks (0.383 and 0.382), which were mostly untrained and never had time to separate channels either. The local math was right; the conclusion went a bit too far. That pattern — correct edge arithmetic, shaky semantic leap — will return in the next lesson.

005Lesson 5 · When memory beats math~8 min

What the AI got wrong: when memory beats math

This is where the story flips. The last lesson showed two things the AI could do by doing simple arithmetic at the edges of the network. Here we look at three times it got the meaning wrong — with exact accuracies and confidences from the paper.

First, the fast-food test. Three different nets were trained on photos of fast food — burgers, sushi, tacos and so on. Their accuracies were modest: Model 1 54.67%, Model 2 52.67%, and the Random-architecture net 58.00% (on only 300 test images). They were also lightly trained: 95.8% of Model 1's first-layer weights were still inside their starting range. All three were called CIFAR-10 at 45%, 50% and 60% confidence. All three share CIFAR-10's famous footprint — a 32 by 32 color image with 10 outputs — and that shape pulled the guess. One session even admitted its choice “rests on how common it is, not on the weights.”

Second, KMNIST. These are images of Japanese handwritten characters, padded to 32 by 32 and copied to three color channels. Both Model 1 and Model 2 were called MNIST — the more famous handwritten-digit dataset — at 80% and 85% confidence. The local math was partly right: both sessions ruled out color datasets. But the final name picked the famous cousin. Part of the error was baked into preprocessing: the background value should have been about −0.47, the sessions estimated −0.41 and compared it to the standard numbers for MNIST (−0.42) and KMNIST (−0.55), so KMNIST looked like the worse match.

The crucial distinction: reading a preference is not naming it. Finding that a feature votes strongly for output 4 is real reading. Deciding output 4 means “frog” adds a memorized label from a different dataset.

The clearest example is SAT-6, a satellite land-cover dataset with six classes: barren land, building, grassland, road, trees, and water. The high-accuracy Model 2 net scored 99.57% — almost perfect. It was still read as CIFAR-10 photos of animals at 70% confidence for image type and 45% for classes, with 0 of 6 classes right.

What happened? The session correctly spotted a “dark green” feature. In checks, that feature correlates +0.64 with greenness and −0.01 with brightness, fires most on trees, and its strongest vote across all 78 hidden units goes to output 4 — which is trees. The session kept the first half (“green feature favors output 4”) and replaced the second half with “output 4 is frog,” to fit its CIFAR-10 animal story. A second feature it labeled “blue” actually correlates −0.44 with blueness and fires most on grassland and road, not water — yet it was used to justify “output 0 is bird.” Same pattern: the numeric link was true; the word came from memory.

Try it below: switch between the three failures and toggle the famous-dataset prior off and on. Watch how the bar heights — the real votes from the weights — stay exactly the same while the labels on top of them flip from true to memorized.

006Lesson 6 · The detective test~7 min

The permuted-label detective test

On the normal CIFAR-10 test, Claude looks like it can really read. Both networks were named "CIFAR-10" with high confidence — 90% and 92% — and the clue it used was real: in the last layer, seven hidden units shared the same sign pattern that split outputs {0,1,8,9} from {2,3,4,5,6,7}. In standard CIFAR-10 that is vehicles vs animals. The next most common pattern had only three units, so the split stood out. Even the first principal component separated the same two groups.

But that success has a hidden shortcut. If all you have memorized is "outputs 0,1,8,9 are vehicles," you will get the normal test right without ever following the wiring from pixels through the middle layers. You just need to spot the numeric cluster at the end and attach the famous names.

The detective trap that keeps the wiring but moves the names

So the audit set a trap. It kept the exact same learned weights and just renumbered which output meant which class — vehicles were moved to outputs 2,4,5,7. Accuracy stayed the same, 82.37% vs 82.36% originally, and the weight structure moved with it. A reader that truly traces signals from input pixels to outputs should still call the 2,4,5,7 cluster vehicles, because the wiring still points there.

A reader that is matching a memorized template will do the opposite: it will keep the old names and put them on the wrong outputs.

That is why the permuted-label test is the key check in the paper. It preserves what the network learned, but breaks the link between where a cluster sits and what a memorized list says it should be called.

What happened? In that single permuted run, Claude did find the split at the new indices — it correctly reported the cluster at 2,4,5,7. That part is genuine local arithmetic at the output edge. Then it said the clusters "match the standard label order" and named nine class pairs, all wrong. Output 2, which is really airplane, was called bird. Output 4, really automobile, was called deer. It even noticed one odd detail — cat and dog seemed anti-correlated — and listed it as evidence against CIFAR-10, but never considered that the labels might simply be reordered. Confidence was still 72%.

There was one more control to see what happens when the structure itself is destroyed. When values were scrambled inside each weight array, accuracy fell to 7.78% — worse than chance at 10%. Claude noticed the vehicle/animal contrast had almost vanished (0.0031 vs 0.0103 before) and lowered confidence to 45%, but it never noticed the scrambling and still claimed the weights supported "colour natural images."

Together, the two controls tell a clear story: the arithmetic at the edges survives — finding the cluster — but the meaning attached to it does not, because that meaning came from a familiar template, not from tracing the middle of the network.

007Lesson 7 · So can it reason?~7 min

Two kinds of reading — and why confidence lies

Think of reading a novel by opening only the first chapter and the last page. You can tell a lot — who walks in the door, who ends up together — but you miss the middle where the clues connect. The paper found Claude reads weights the same way.

In its own words, it read conv1 and the final fc2 output layer closely and only sampled the middle. For example it traced class evidence for just 7 of 77 channels in one layer, and used only 10 to 18 of 78 hidden units for another. Those outer layers are where the easy, low-dimensional statistics live: the batch-norm running variance near $0.9^{3}=0.729$ that reveals about three training steps, or the sign pattern in the last weight matrix that splits CIFAR-10 outputs into vehicles and animals with 7 hidden units sharing one pattern versus 3 for the next.

When the middle has to carry the meaning, sampling breaks. One Cats vs Dogs session looked at 10 hidden units and claimed evidence fell steadily from top to bottom — $0.33, 0.28, 0.23, 0.16$ — and built a story about heads and ears at the top of the image. Across all 78 units the true order is $0.109, 0.144, 0.107, 0.092$: the peak is in the second row, not the top. Another session called a deep SAT-6 feature "blue" to justify calling output 0 bird, but its correlation with blueness is $-0.44$ — it fires most on green grassland and road, not water.

The paper's two-level account: real local arithmetic at the edges — initialization bounds, batch-norm defaults, output-layer signs — plus dataset priors for semantics. Finding that a feature prefers output 4 (which is $trees$ in SAT-6) is reading; deciding output 4 means $frog$ is remembering CIFAR-10.

That also explains why confidence is a poor guide here. Wrong answers came with high confidence: KMNIST called MNIST at 80% and 85%, and the 99.57%-accurate satellite network called CIFAR-10 animals at 70% for image type. Confidence did drop sensibly elsewhere — CIFAR-10 from 90% to 72% when labels were permuted to 45% when weights were shuffled, Cats vs Dogs at 30–35%, the barely-trained SAT-6 network at 30% and 3% — but with mostly one run per condition you cannot trust any single number as calibration.

This was an exploratory audit, not a final verdict. It tested only Claude Opus 5.5 in one no-tools mode, mostly single runs, with no direct test of tracing a concrete input to its exact logits, and every network kept the same $32\times 32$ input size. It also does not refute editing results like Takehi et al.'s MATH-500 jump from 7.9% to 48.1%; an edit can still help even if the story about reading is prior-driven.

ABCWord bank

Word bank.

weights (parameters)

The numbers a neural network learns during training. They decide how strongly one part of the network influences the next.

logits

A prediction from the network before it is turned into a probability. The biggest logit usually becomes the predicted class.

CNN (convolutional neural network)

A common kind of image-recognition network. It slides small filters over the image to find patterns like edges.

filter / kernel

A tiny square of weights, like 3x3 numbers, that scans for a pattern such as a vertical edge or a patch of green.

batch normalization

A layer that keeps numbers tidy during training by subtracting a running average and dividing by a running spread. Its running statistics change a little with each training step.

optimizer (Adam)

The step-by-step rule that nudges weights to make fewer mistakes. Adam is one popular rule.

dataset

The collection of images a network was trained on, for example CIFAR-10 (planes, cars, cats, frogs) or SAT-6 (satellite land-cover).

dataset prior / memorized template

When a model leans on what it has memorized about famous datasets, like '32x32 with 10 outputs usually means CIFAR-10', instead of really analyzing the weights.

label permutation

Keeping the same learned weights but changing which output number means which class. Perfect for testing if a model really follows the wiring or just remembers the usual order.

weight-space programming (WSP)

Claim that a general LLM can read, write and edit another network's raw weights directly from text, without running it.
