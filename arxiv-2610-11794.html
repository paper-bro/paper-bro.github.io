001Lesson 1~8 min

Dropped into a game with no instructions

Imagine waking up inside a puzzle game with no instructions. You see a 64 by 64 grid of colored squares, a few arrow keys, and nothing else. No source code, no tutorial, no sentence that says "your goal is...". How do you learn to win within a tight move limit?

This is the problem the paper studies using ARC-AGI-3 puzzles, and it describes each puzzle precisely as a partially observable Markov decision process:

$$\mathcal{M}=\langle \mathcal{S},\mathcal{A},\mathcal{O},T,\rho,G\rangle$$

Think of it in plain words: $\mathcal{S}$ is every possible hidden state of the game board, $\mathcal{A}$ is your actions like UP or CLICK, $\mathcal{O}$ is what you actually see (the colored grid), $T$ is the hidden rule that decides the next state — written $s_{t+1}=T(s_t,a_t)$ —, $\rho$ decides what you see from that state — $o_t=\rho(s_t)$ —, and $G$ is the unknown set of goal states. The agent never sees $T$, $\rho$, or $G$ directly.

All it gets is its interaction history and a little completion signal. After $t$ real moves, that history is:

$$H_t=(o_0,a_0,o_1,\dots,a_{t-1},o_t),\;\; c_t=\mathbf{1}[s_t\in G]$$

$o_0$ is the first grid, $a_0$ your first action, $o_1$ the next grid, and so on. $c_t$ is just 1 if you are at the goal, 0 otherwise. The paper's Figure 1 is not shown here, but its idea is simple: every real move counts against a budget $B$.

The goal is to succeed fast. Let $\tau_G$ be the first step you hit $G$. The primary aim is to maximize success probability within budget:

$$p_B=\Pr(\tau_G \le B)$$

and then, among winners, to minimize expected steps $c_B=\mathbb{E}[\tau_G\mid\tau_G\le B]$. Crucially, only real actions count. Thinking, simulating futures in your head, or replaying old moves to test an idea costs zero.

The core trap: a short history can be explained by many different hidden rules that all reproduce the past but predict different futures. The paper's example: if every wall you have seen sits at column 7, then "a box stops at a wall" and "a box stops at column 7" look identical — until a wall appears elsewhere.

That is why replaying the past is not enough. A world model can get every past grid exactly right and still be wrong about the next grid. You have to guess the hidden $T$ and $G$, test that guess with new actions, and revise when prediction and observation disagree.

In the lab below, try it yourself. You will move in a tiny 5 by 5 slice of such a grid. A hidden world rule and your model's rule both fit the first few pushes against a wall. Move somewhere new and watch when the same past leads to different predictions.

002Lesson 2~7 min

A frozen brain with a notebook that keeps learning

Most AI learning works like studying for an exam: you rewire the brain itself. You change millions of tiny dials inside the model until it gets more answers right. That is powerful, but also slow and hard to inspect.

Memento tries the opposite. It freezes the brain. In the paper this is written as $\phi_{t+1}=\phi_t=\phi$: the big language model's weights $\phi$ stay exactly the same over time $t$. Nothing inside is rewritten. All learning happens outside, in files the frozen brain can read and edit — a bit like you keeping the same head but getting better and better notebooks.

Freezing the brain does not mean freezing learning. It means the place that learns moves from inside the model to outside it.

That outside learning has three parts, called the learning state $Z_t = (H_t, \psi_t, \theta_t)$:

📼

$H_t$ — history

The episodic evidence: every picture seen $o$ and action tried $a$, in order, like a tape: $H_t=(o_0,a_0,o_1,\dots,o_t)$. Plus whether the level said "done".

📖

$\psi_t$ — rulebook

The semantic memory: beliefs in plain English in world_model.md. Objects, how moves work, what counts as a goal. Revisable and often underspecified.

⚙️

$\theta_t$ — executable

The compiled program in world_model_engine.py. It turns those sentences into code a planner can actually run.

Earlier Mementos already used notebooks, but for different jobs: first remembering what happened (episodes), then how to act (reusable skills). Memento 3 adds a third kind: how the world works. That is model memory. It must survive across many levels, because a rule you learn in level 2 may only be tested in level 7 when a new mechanic appears.

This is why the paper stores everything in Git. Without version control, each edit overwrites the last — a bad revision can erase a good rule with no way back. With Git, every $\psi$ and $\theta$ is committed and tagged with its iteration. The agent — and you — can look at diffs, compare two rulebooks side by side, or restore an old program that used to work. The repository is not just a backup; it is the agent's memory of how its own understanding changed.

Try it below. Run the same frozen brain through 10 short tasks three ways: with no notebook, with a notebook but no Git, and with a notebook plus Git. Watch what happens after task 6, when a mistaken edit breaks the rulebook. Notice which $Z_t$ survives the mistake and which gets to rewind.

003Lesson 3~9 min

Two copies of what you believe: words and code

Your AI doesn't keep its understanding of the world locked inside its head. It writes it down in two linked forms — one you can read, and one a planner can run thousands of times a second.

The reading copy is the rulebook, written as world_model.md. The paper calls it $\psi$ (psi) and says $\psi \in \Psi$ — just meaning "one rulebook chosen from the space of all possible rulebooks." In it the agent writes plain sentences: what objects exist, what each key does, how the badge changes, what counts as winning. A sentence might be: "stepping on the painter turns the badge purple."

The running copy is the executable, written as world_model_engine.py. The paper calls it $\theta$ (theta) with $\theta \in \Theta$ — "one program from the space of all programs." It has to do four concrete jobs, so a planner can ask "what if I do this?" without touching the real game:

  • Initializer $\iota_\theta: O \to \hat{S}_\theta$ — read the first picture $o_0$ you see and build an internal state $\hat{s}_0$. That state can remember hidden things, like how much refill you have left, even if the current frame doesn't show it.
  • Transition $f_\theta: \hat{S}_\theta \times A \to \hat{S}_\theta$ — given an internal state and an action, predict the next internal state. This is where most rules live as if branches.
  • Observation predictor $\rho_\theta: \hat{S}_\theta \to O$ — turn that next internal state back into what you'd expect to see: the next 64×64 grid.
  • Goal set $\hat{G}_\theta \subseteq \hat{S}_\theta$ — the agent's current guess at "what counts as winning." If $\hat{s}$ is in there, the agent thinks the level is done.
Think of $\psi$ as the recipe card and $\theta$ as the robot that actually cooks. The card says "add salt if soup is bland"; the robot has an if bland: add_salt() branch it can execute.

To make a prediction the executable replays. Start from the first picture:

$$\hat{s}_0 = \iota_\theta(o_0),\quad \hat{s}_{i+1}=f_\theta(\hat{s}_i,a_i)$$

That rebuilds where the agent thinks it is now, $\hat{s}_\theta(H_t)$. Then to guess the next frame after a new action $a_i$:

$$\hat{o}_\theta(H_i,a_i)=\rho_\theta\big(f_\theta(\hat{s}_\theta(H_i),a_i)\big)$$

In words: take the replayed state, apply the transition for $a_i$, and render what that would look like.

A rulebook can leave details blank. The paper writes $[\![\psi]\!] \subseteq \Theta$ for the denotation of $\psi$ — all programs that faithfully do what $\psi$ says. If $\psi$ says "walls block movement" but doesn't say what happens on a refill, many different programs are in $[\![\psi]\!]$. Turning a vague sentence into exact code is what compilation does, and an underspecified rulebook is why two different executables can both pass the same checks at first.

Figure 1 shows this mapping in the real game. Numbered sentences in the rulebook — change the badge pattern, change its colour, collect a refill, match badge to door — each become a numbered if branch in the transition function. With all branches in place the planner can simulate a whole route: paint, stamp, pick up refill for extra moves, and reach the matching door without running out of budget. Delete a branch and the simulated future forks a different way.

Try it below: toggle each numbered rule on and off. Watch the matching branch dim in the code and see the predicted path replan — or disappear — when the executable no longer knows how to change the badge or respect a wall.

004Lesson 4~10 min

Spot the mistake, fix the idea, prove it works

You predicted the badge would mirror. You touch it, and instead it spins clockwise. Your world model is wrong. What now?

In Memento 3 the frozen language model never changes its own weights. All learning happens outside it, in two files it edits: the rulebook ψ and the program θ. Every interaction runs through the same 5-stage loop — diagnose, edit, test, like a science lab.

The 5 stages (in order):
  1. Observation. Do at, get ot+1. Append to the history: Ht+1 = Ht ‖ (at, ot+1).
  2. Reflection. The frozen LLM compares prediction ôθ with reality and picks one of three moves: D = {retain, revise_rulebook, repair_code}.
  3. Rule revision. If it chose revise_rulebook, it rewrites the English rule: ψ̃ = Δφ(ψ; Ht+1). Otherwise ψ stays.
  4. Compilation. A compiler turns the (possibly new) rulebook into code: θ̃ ∼ Cφ(·| θ, ψ̃, Ht+1).
  5. Verification. Two gates. Pass both and the new pair becomes ht+1 = (ψt+1, θt+1). Fail either and you loop back.

Stage 2 is the fork that matters. repair_code means “my idea is right, my code has a bug.” The English rulebook does not change, only the Python branch does. revise_rulebook means “my idea is wrong.” You must first rewrite the English rule, then compile. Only a rule change records a new hypothesis about how the world works.

$$ \theta_t \in [\![\psi_t]\!] \quad\text{and}\quad \hat{o}_\theta(H_i,a_i)=o_{i+1}\;\; \forall i<t $$

In words: gate 1, fidelity — an LLM judge checks θ ∈ ⟦ψ⟧, that the code faithfully does what the rulebook says. Gate 2, replay — on every recorded transition, the program's predicted next picture must match the real picture cell-for-cell on the 64×64 grid. The paper writes this as verify(θ;Ht) = Π 1[ô = oi+1], which is 1 only if all cells match, on all frames.

Only pairs passing both gates enter the admissible set Vt and update the point belief b̂t+1 = δ(ht+1, ŝ) used for the next plan. Figure 2 shows exactly this: a badge thought to mirror is seen rotating clockwise, reflection replaces the rule, it is compiled, and both checks must pass before planning resumes.

Watch which choice clears both gates.

Next: Many Stories, Simplest Wins? →
005Lesson 5~8 min

When many theories fit the clues

Imagine you watch six moves of a new board game and every one makes sense. You write a rule that predicts all six perfectly, and your friend writes a totally different rule that also predicts all six perfectly. Who is right? You can't tell yet — you haven't seen the seventh situation where they disagree.

That is exactly what happens inside Memento 3. After the agent has collected a history Ht, it checks each new program with cell-exact replay: does it predict every cell of every past 64×64 frame? The set that passes is called Θt = { θ : verify(θ; Ht)=1 }. In a tricky puzzle Θt can stay big — many programs survive.

Worse, the past alone cannot rank those survivors. The paper shows this as:

$$\frac{p(\theta \mid H_t)}{p(\theta' \mid H_t)} = \frac{p(\theta)}{p(\theta')}$$

for any two survivors. In words: if two programs both explain everything you have seen, your history keeps their prior odds unchanged. Verification removed the wrong programs, but it does not tell you which survivor is true. That leftover set is called the version space.

So how does the agent pick? It uses a tie-breaker the paper calls SimplifyLLM: prefer the shortest combined description.

The ideal it approximates is:

$$ (\psi_t, \theta_t) \approx \arg\min_{(\psi,\theta)\in\mathcal{V}_t} \,[\,\mathcal{L}(\psi) + \mathcal{L}(\theta\mid\psi)\,] $$

ℒ(ψ) is how long the rulebook needs to be, and ℒ(θ|ψ) is how much extra code is needed given that rulebook. Shorter = simpler. This matches a prior μ0 ∝ 2−ℒ: simpler rulebooks start more likely. Among all admissible pairs 𝒱t that pass both replay and the LLM's fidelity check θ ∈ ⟦ψ⟧, the shortest maximizes the posterior μt. It is a practical bet, not a guarantee — the shortest story can still be wrong on an unseen state.

Once a pick is made, the planner treats it as true and computes a shortest-path value:

$$ V_{\theta}(x)=0 \text{ if } x\in\hat G_{\theta},\quad V_{\theta}(x)=1+\min_{a} V_{\theta}(f_{\theta}(x,a)) \text{ otherwise} $$

In plain English: distance to goal under this model. It then follows the minimizing actions as planθ. If Vθ=∞ — the model thinks there is no path — the agent does not keep pushing the same plan. It asks the LLM for an intermediate target to explore, like testing an unexplained object, and searches for a short route to that instead.

Figure 5 shows this evolution in game tr87 across eleven versions. At first the rulebook holds two rival ideas about glyph orientation. Interaction then establishes that a letter stays the same letter when rotated, and replaces pixel coordinates with a "glyph-box" rule. Later levels force the cursor rule to flip entirely — what was "only moves right" becomes "moves both ways." Each red claim is kept until new evidence turns it green and rewrites it.

006Lesson 6~9 min

Don't bet on one guess — bring a team

Imagine you have one detective who is convinced the culprit always wears blue. She only visits the blue-clothes shop, always finds someone in blue, and never learns she is wrong — her plan never takes her where the evidence could prove her wrong.

This is the single-model trap. The paper writes it as E(θ) ∩ R(θ) = ∅. R(θ) is every history you can reach while following model θ's own plan. E(θ) is every history where model θ would predict the next picture wrong. If those two sets never overlap — Eq. 28–29 in the paper — the model looks perfect forever, even when it is wrong about unseen states.

The trap: A world model can be self-confirming. Rewriting the same wrong idea in nicer words does not fix it. You need different actions that visit the states where it would fail.

Memento 3's fix is to bring a team. Instead of one pair (ψ,θ) — a rulebook plus its program — keep N of them in parallel:

$$\Phi_t = \{(\psi_t^i, \theta_t^i)\}_{i=1}^{N} \subseteq \mathcal{V}_t$$

This is Eq. 30. Φt is the population at step t. Each member is already admissible, meaning it passed the two gates from last lesson: faithful to its rulebook and exact replay on history. N=1 is just the single-model case you already know.

The team shares one history Ht. Every real move, no matter which teammate planned it, is added to the common record and every teammate is checked against it. A bump that falsifies one model becomes evidence for all. The team's belief is the average of its members:

$$\hat b^{(N)}_t = \frac{1}{N}\sum_{i=1}^{N} \delta_{(h^i_t,\,\hat s_{\theta^i_t}(H_t))}$$

Each δ is a pin that puts all probability on one member's hypothesis and its replayed state. More pins means more places to start planning from.

But the team should keep different plans, not just different code. Two programs can look different yet produce the exact same move sequence. The paper groups them by behavior:

$$\theta \sim_{H_t} \theta' \iff \mathrm{plan}_\theta(\hat s_\theta(H_t)) = \mathrm{plan}_{\theta'}(\hat s_{\theta'}(H_t))$$

Eq. 32 says: two models are behaviorally equivalent at the current history if their plans — the shortest path to the goal under each model — are identical step for step. The system then samples uniformly over distinct plan-classes, not over models, so three copies of the same idea don't get three votes.

Slightly deeper: For each episode the controller picks a class [θ] ~ Uniform(Φ̂t) and follows its representative's plan āt:t+K-1 until success or mismatch (Eq. 33). Then all falsified members are repaired through the reflect–revise–compile–verify loop from Lesson 4.

The three jobs repeat: Propose new admissible pairs, Repair every member that just failed replay, Plan/Act from a sampled survivor. On the hardest public game wa30 (9 levels, 1,843 human moves), N=2 cleared all levels with 597 actions versus 899 for N=1 — 0.66× the cost (Table 4), and needed no extra reasoning budget. Same brains, broader exploration.

In the lab below, the hidden wall is at column 4 but each teammate guesses a different column. With N=1 the agent loops in its own favorite corridor and never hits the truth — watch E∩R=∅ stay YES. Raise N to 3–5 and turn shared history on, then run episodes: different plans cover new cells, bumps falsify wrong guesses faster, and coverage jumps.

007Lesson 7~10 min

Putting rules to work on ARC puzzles

On paper, “rulebook plus executable” sounds abstract. In the actual ARC-AGI-3 system, it is just two files that sit next to each other in a folder.

Two files, two jobs. world_model.md is the rulebook — plain English sentences like “walls block movement” or “stepping on the badge copies its colour to the door.” world_model_engine.py is the executable — Python code compiled from those sentences. It contains four pieces: an initializer ιθ: O → Ŝ that builds an internal state from the first picture o0, a transition predictor fθ: Ŝ × A → Ŝ that says how that internal state changes with an action, an observation predictor ρθ: Ŝ → O that renders the next 64×64 grid, and a guessed goal set Ĝθ that says “this counts as solved.”

Before the agent trusts any executable for planning, it must pass a very strict test.

Cell-exact replay, not “looks about right.” The verifier replays every recorded trajectory from its own first picture, applying fθ and ρθ at each step, and checks that every single cell of every predicted 64×64 frame matches the recorded frame exactly. One wrong pixel = fail. It also asks the frozen language model: does this code faithfully implement the rulebook in ⟦ψ⟧? Both checks must pass.

Planning from a reconstructed state. The agent never sees the true hidden state st. Instead it reconstructs its best guess by replaying the whole history under the current executable:

$$\hat{s}_0^{\theta}=\iota_{\theta}(o_0),\quad \hat{s}_{i+1}^{\theta}=f_{\theta}(\hat{s}_i^{\theta},a_i),\quad \hat{s}_{\theta}(H_t)=\hat{s}_t^{\theta}$$

In words: start from the first picture, simulate each recorded action with your current world model, and the result ŝθ(Ht) is where you think you are now. The planner then searches from there for a shortest path to Ĝθ that fits in the remaining budget B−t. If the shortest-path length Vθ is finite, it follows the first action; if at any step the real next picture disagrees, it stops immediately and sends that mismatch back to reflection.

This matters because observation is not the same as state. In game ls20, for example, fog of war hides tiles outside your local view — the current 64×64 frame does not show the whole maze. The executable's internal state Ŝ must remember what was behind the fog, or it cannot predict correctly. The same replay mechanism that verifies also rebuilds that memory after every revision.

And it never stops. The harness keeps the full history Ht across levels, commits each new ψ and θ to Git, and later levels can introduce entirely new mechanics that force another round of rule revision. The paper goes further than this lesson into how those Git versions are used to restore broken hypotheses — here we focus on the build-verify-plan loop itself.

008Lesson 8~9 min

The scoreboard: from puzzles to Pong

Memento 3 started with a claim: a frozen language model — one that never changes its weights — can keep getting better just by rewriting its own notebook and code. Now we check if that claim holds on a real scoreboard.

On ARC-AGI-3, the test is tough. Each of the 25 public games has 6 to 10 levels, 183 levels in total. You see only a 64×64 color grid and the buttons you can press. You never see the game’s source. You have a strict action budget, and every move counts — even failed tries and resets. Model building and replay checks do not count.

The single-model agent — one rulebook world_model.md plus one program world_model_engine.py — clears every level of all 25 games. Its mean RHAE is 100.0, the ceiling. To hit 100 you must clear everything and be efficient: the level-weighted efficiency $e_{\ell}=\min\{1.15,(h_{\ell}/a_{\ell})^{2}\}$ has to average at least 1, where $h_{\ell}$ is the human move count and $a_{\ell}$ is yours.

The headline: 7,518 actions total vs 17,135 for humans — 44% of the human count. The next best system, baseline1, also clears all 25 but needs 8,347 actions (49% of human). The others leave games unfinished: OPINE-World 20/25, NOOA 19/25. And against the same backbone with the Standard Harness (Claude Opus 5 alone), Memento 3 is 59.3 RHAE points higher.

That average hides the range. On the easiest win, game m0r0, it uses 0.20× the human moves; on the hardest of its wins, lf52, it still uses 0.67×. The median across the 25 is 0.42× — less than half.

Was the rulebook just decoration? The authors ablated it: same harness, same verifier, same backbone, but no $\psi$ file — code only. On three games spanning easy to hard (ft09, ka59, cn04) both versions still solved everything, so we compare how fast they converged. With the rulebook: 617 actions and 678 agent turns. Without: 677 actions and 830 turns. That is 9% fewer actions and 18% fewer turns with the rulebook. Think of it as the difference between solving the puzzle and solving it without needing to start over as often. The persistent words helped the code settle.

The same loop — write rules, compile, check cell-exact replay, plan — then went to a totally different job: Atari Pong. Here there are no levels, just real-time steering. The rulebook learned ball physics, paddle motion, and the opponent, then was compiled into a feedback controller that plays with no language-model calls at runtime, just like a trained RL policy.

Learning took 9,504 emulator frames. The controller then won 21:0 in all three evaluated episodes, each with a different opening. For scale, the model-free RL baselines in Table 5 needed $2.0\times 10^{8}$ frames — about 21,000× more — and the best model-based RL baselines needed $4.0\times 10^{5}$ frames — 42× more. The same LLM with no world model scores −19 (random is −20.7). Figure 9 shows why the rulebook mattered: the bounce rule went from a 4-band guess that forbade flat returns, to a centered-deflection formula that allowed $v_{y}=0$ but shot too high, to the final asymmetric map with $|v_{y}|\leq 2$. Each revision was written first in words, then in code.

ABCWord bank

Word bank.

interaction history H<sub>t</sub>

The AI's record of what happened: every picture it saw and action it tried. Written as H<sub>t</sub> = (o<sub>0</sub>,a<sub>0</sub>,o<sub>1</sub>,...o<sub>t</sub>).

POMDP

A model of a world where some things are hidden. Defined by states S, actions A, observations O, how the world moves T, what you see ρ, and goal states G. The paper treats ARC-AGI-3 and Pong this way.

frozen LLM

The AI's big language model. Parameters φ never change: φ<sub>t+1</sub>=φ<sub>t</sub>=φ. All learning happens outside it, in files it can edit.

learning state Z<sub>t</sub>

All the AI can edit while playing: (H<sub>t</sub>, ψ<sub>t</sub>, θ<sub>t</sub>) — history, rulebook, and program. This is its evolving memory.

rulebook ψ

A Markdown file world_model.md where the agent writes its current beliefs about objects, actions, and goals in plain English. Lives in Ψ, the space of rulebooks.

executable θ

A Python file world_model_engine.py compiled from the rulebook. It has an initializer ι<sub>θ</sub>, a next-state predictor f<sub>θ</sub>, an observation predictor ρ<sub>θ</sub>, and a guessed goal set Ĝ<sub>θ</sub>. Lives in Θ.

denotation ⟦ψ⟧

All programs that correctly do what a rulebook says. Written ⟦ψ⟧ ⊆ Θ. One rulebook can allow many programs if it leaves details unsaid.

verification / replay

The check that an executable predicts every past picture correctly: ĥo<sub>θ</sub>(H<sub>i</sub>,a<sub>i</sub>) = o<sub>i+1</sub> for all i < t, cell-by-cell on the 64×64 grid. Must pass plus an LLM check that code matches the rulebook.

version space

All programs that could explain the same past but disagree somewhere unseen. Replay alone cannot pick the right one.

minimum description length (MDL)

The paper's bias: prefer the shortest rulebook + shortest code among those that pass verification. Ideally ψ<sub>t</sub>,θ<sub>t</sub> = argmin [ℒ(ψ)+ℒ(θ|ψ)]. Corresponds to a prior μ<sub>0</sub> ∝ 2<sup>-ℒ</sup>.

RHAE

ARC-AGI-3's score: e<sub>ℓ</sub>=min{1.15,(h<sub>ℓ</sub>/a<sub>ℓ</sub>)²} per level, weighted by level number. 100 is the ceiling and needs every level cleared efficiently vs humans.

population Φ<sub>t</sub>

Keeping N rulebook+program pairs in parallel, sharing the same history H<sub>t</sub>. Approximated belief b̂<sup>(N)</sup><sub>t</sub> = 1/N Σ δ<sub>(h<sup>i</sup>,ŝ)</sub>. Sampling different plans helps escape a wrong but self-confirming model.

Git memory

Saving every ψ and θ version in Git with commits and tags, so the agent can diff or restore old hypotheses instead of overwriting them.

feedback controller

Using the learned program to pick actions repeatedly from new observations, like steering in Pong, without calling the LLM at runtime.

shortest-path value V<sub>θ</sub>

The planner's estimate: length of shortest path from a state x to goal under model θ, using V<sub>θ</sub>(x)=1+min<sub>a</sub> V<sub>θ</sub>(f<sub>θ</sub>(x,a)). Infinite if no path.
