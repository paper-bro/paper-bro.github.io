001Lesson 1 — The problem~6 min

Why Can't Transformers Read a Whole Book at Once?

Imagine trying to read a whole novel in one glance. To understand the last sentence, you check every earlier sentence for clues — who “she” refers to, what was promised on page 12. If you did that for every word, the checking explodes: 1,000 words means ~1 million checks, 10,000 words means ~100 million.

That is exactly what the Transformer’s famous trick — softmax attention — does. For each position i, it builds a query q(i) (“what I need”), compares it to every previous key k(j) (“what I contain”), and mixes the matching values v(j). In symbols the paper writes:

$$ y^{(i)} = \sum_{j \le i} \text{softmax}\!\left(\frac{q^{(i)\top}k^{(j)}}{\sqrt{d_k}}\right) v^{(j)} $$

Here q(i),k(i) ∈ ℝdk are short vectors, v(i) ∈ ℝdv is the content, and the softmax turns raw scores into weights that sum to 1. Powerful — any word can directly retrieve any earlier word — but the price is that pairwise table. Training on length T needs on the order of T × T comparisons. The paper calls this quadratic cost O(T²) in time and memory.

The way out is linear attention. Instead of keeping the giant table, keep a single fixed-size memory matrix W. Each new token does one quick write to W and each query does one quick read: total work grows like T, not T². During reading (inference) the cost per new token stays constant, because W never grows with the book. How that trick works — and what it loses — is the rest of the course.

This paper tests that bargain honestly. All main models are 350-million-parameter decoders trained on FineWeb-Edu text with the LLaMA2 tokenizer, usually to 15 billion tokens at sequence length 4,096. It also measures how iteration time scales as length stretches to 32,000 tokens, and spot-checks larger 1.3B/40B-token and 3B/60B-token DeltaNet runs. Later lessons will dig into the four linear memories the paper compares in the same notation and same setup.

The goal is not to crown one “best” model. The paper maps a frontier: lower validation loss (better predictions) versus higher throughput (tokens per second) versus flatter scaling to long context. Every design moves you somewhere on that trade-off.

002Lesson 2 — How attention retrieves~8 min

How Softmax Attention Finds the Right Memory

Imagine you are reading a sentence and hit the word "it". To know what "it" means, you glance back at every previous word and ask: how well does each one match what I'm looking for? Softmax attention is that glance, turned into math.

Each position in the sequence makes three little vectors from its word. The query $q^{(i)}$ is the question the current token asks: "what do I need?" The key $k^{(j)}$ is the label on a past token: "this is what I contain." The value $v^{(j)}$ is the actual content to copy over if there's a match. $i$ is where you are now, $j$ runs over you and all tokens before you. $d_k$ is just the length of the query and key vectors.

The paper writes the whole operation as one formula (Eq. 1 in the paper):

$$ y^{(i)} = \sum_{j \le i} \frac{\exp\!\left(q^{(i)\top} k^{(j)} / \sqrt{d_k}\right)}{\sum_{\ell \le i} \exp\!\left(q^{(i)\top} k^{(\ell)} / \sqrt{d_k}\right)} \, v^{(j)} $$

Read it inside out. $q^{(i)\top} k^{(j)}$ is a dot product — a single number that is big when query and key point the same way (good match) and small or negative when they don't. Divide by $\sqrt{d_k}$ to keep numbers from exploding. Then $\exp()$ — the exponential — makes big matches much bigger and squashes negative matches toward zero. Finally, divide by the sum of all those exponentials so the weights add to 1. The result is a weighted average of the values: $y^{(i)}$ is mostly the values whose keys matched best.

Why the $\exp$ and the divide? Without them you'd just have raw similarity scores — a flat, blurry mix. The exponential sharpens: a slightly better match can get most of the weight. The normalization guarantees soft selection — the weights always sum to 1, like percentages of attention.

This is why softmax attention is expressive: token $i$ can in principle pull information from any earlier token, with sharp, selective focus. The price is that it must compute that dot product for every $i,j$ pair explicitly — the $T \times T$ matrix the paper wants to avoid. Linear attention will try to get the same effect without that matrix.

Try it yourself below. Drag the similarity bars to act as the query, change the divisor $\sqrt{d_k}$, and toggle softmax on and off. Watch how the exponential turns a modest lead into dominant focus, and how the output $y$ snaps from a blurry average to a sharp retrieval.

003Lesson 3 — The linear trick~9 min

Replacing Pairwise Comparisons with a Running Memory

Imagine softmax attention as checking every sticky note on a wall, one by one, for every question. Fast with 100 notes. Impossible with 30,000. The paper asks: can we replace the wall with a small filing cabinet that we update as we read?

A trick makes this possible. In normal attention the score is exp(q·k) — the exponential of query dot key. The paper uses a classic approximation:

$$ \exp(q^{\top}k/\sqrt{d_k}) \approx \phi(q)^{\top}\phi(k) $$

Here φ (phi) is a feature map — a simple function that transforms a key or query, for example φ(x)=ELU(x)+1. Once the score is a dot product of transformed vectors, you can swap the order of the sum. Instead of comparing the new query to every old key, you keep a running total.

Key idea: collect, then query. The paper defines a memory matrix that is the sum of all past pairs: W grows token by token, not by comparing all pairs.

In the paper's notation, for token i:

  • k⁽ⁱ⁾ is its key vector, v⁽ⁱ⁾ its value (the content), q⁽ⁱ⁾ its query
  • κ⁽ⁱ⁾ = φ(k⁽ⁱ⁾) is the transformed key, size d_φ
  • W⁽ⁱ⁾ is the memory, size d_v × d_φ — a table mapping key-features to values

Then the two linear-attention equations from the paper (Eq. 4–5) are:

$$ W^{(i)} = W^{(i-1)} + v^{(i)}\otimes \phi(k^{(i)}) \qquad\text{and}\qquad y^{(i)} = W^{(i)}\,\phi(q^{(i)}) $$

The symbol ⊗ means outer product — make a little table from v and φ(k) and add it to W. Reading is one matrix-vector multiply. No T × T attention matrix ever appears. Cost per token is constant, total cost is linear in length T. The authors also call W fast weights — weights the network writes to and reads itself.

So why not stop here? This naive filing cabinet just adds forever. It has no eraser, no decay, and no sharpening like softmax normalization. As you stuff more pairs into a fixed-size W, they interfere. If two keys point a similar direction under φ, querying one drags in part of the other's value — like two folders with almost the same label getting mixed up.

That interference is the central failure the next lessons fix, starting with DeltaNet. First, get a feel for it below: store two pairs, make their keys overlap, and watch the retrieved value drift from the truth.

004Lesson 4 — Fixing interference~9 min

Don't Write Everything — Just the Surprise

Last lesson you built a tiny filing cabinet: a matrix $W$ that keeps a running sum of everything it sees. Every token did $W \leftarrow W + v \otimes k$ — it just stacked the new paper on top. That's fast, but when two keys look alike, their papers smear together. Ask for A and you get a bit of C mixed in. That's interference.

DeltaNet fixes this with a simple question before writing: "what do I already think this key means?" It checks its own prediction first, then writes only the surprise.

For token $i$, let $k^{(i)}$ be its key and $v^{(i)}$ its true value. The paper writes $\kappa^{(i)} = \phi(k^{(i)})$ for the key after the feature map $\phi$, and defines:

$$\bar{v}^{(i)} = W^{(i-1)}\,\kappa^{(i)}$$

That is the prediction: what the current memory would return if you asked with this key right now. Compare it to what you actually want to store:

$$r^{(i)} = v^{(i)} - \bar{v}^{(i)}$$

$r^{(i)}$ is the residual, or delta — the part the memory doesn't already know. If the memory is already correct, $r$ is near zero and almost nothing gets written.

$$W^{(i)} = W^{(i-1)} + \beta^{(i)}\, r^{(i)} \otimes \kappa^{(i)}$$

This is the DeltaNet update (Eq. 14 in the paper). It looks like the old additive rule, but it adds $r \otimes k$ instead of $v \otimes k$. The term $r \otimes \kappa$ is an outer product — a little table made from the residual and the key — that tells the memory exactly which key-slot to patch. The extra number $\beta^{(i)} = \sigma(w_{\beta}^{\top}x^{(i)})$ in $(0,1)$ is a learned gate: a write strength for this token. Close to 1 means "write the full correction," close to 0 means "barely write." Reading is unchanged: $y^{(i)} = W^{(i)}\phi(q^{(i)})$.

Key idea: Additive memory says "remember this." Delta memory says "remember only what surprised you." Because overlapping keys now correct rather than pile up, retrieval error drops sharply without any extra memory size.

That solves interference, but notice what's missing: DeltaNet has no way to say "forget everything old for a bit." If the document changes topic, stale associations still sit in $W$ and can only be nudged away key by key. The paper calls this the limitation — no explicit global forgetting. The next lesson adds gates that learn when to decay and when to erase.

005Lesson 5 — Controlling forgetting~10 min

Learning What to Keep and What to Erase

Imagine your filing cabinet can only hold one sheet, but you keep adding new sheets on top. After a while you can barely read the important contract underneath. The DeltaNet fix from last lesson — only write what surprised you — helps a lot. But it never throws anything away on purpose. Old junk just sits there.

That is why the paper adds gates — learned dials that decide how much to keep or forget. Think of a gate as a number the model picks for each token, between 0 and 1. 1 means "keep everything", 0 means "erase everything", and 0.8 means "keep 80%". The question is: how fine should that dial be?

Three levels of control

The simplest choice is Gated DeltaNet. Before it reads its memory it decays the whole thing by one number $\alpha^{(i)}$ for that token:

$$ W^{(i)} = \alpha^{(i)} W^{(i-1)} + \beta^{(i)} r_{\alpha}^{(i)} \otimes \kappa^{(i)} $$

Here $\kappa^{(i)}=\phi(k^{(i)})$ is the transformed key, $\bar{v}_{\alpha}^{(i)}=\alpha^{(i)}W^{(i-1)}\kappa^{(i)}$ is the prediction from the decayed memory, and $r_{\alpha}^{(i)}=v^{(i)}-\bar{v}_{\alpha}^{(i)}$ is the surprise. $\beta^{(i)}$ still controls how hard to write. This is coarse: one knob dims the entire memory at once. Good for "clear the desk", bad for "keep the contract but toss the ads".

Kimi Delta Attention makes the dial per-channel. Instead of one $\alpha$, it learns a vector $\bm{\alpha}^{(i)}$ with a different value for each key-feature column, packed into a diagonal matrix $D_{\alpha}^{(i)}$:

$$ W^{(i)} = W^{(i-1)} D_{\alpha}^{(i)} + \beta^{(i)} r_{\bm{\alpha}}^{(i)} \otimes \kappa^{(i)} $$

Right-multiplying by $D_{\alpha}$ means: decay column by column along the key dimension. If spam lives in columns 0-2 and contracts live in columns 3-5, the model can keep one subspace while aggressively forgetting the other. When every entry of $\bm{\alpha}^{(i)}$ is the same number $\alpha^{(i)}$, this collapses exactly back to Gated DeltaNet.

Gated DeltaNet-2 goes one step further and splits the write itself. One scalar $\beta$ used to control both "erase old stuff at this key" and "write new stuff". GDN-2 gives them separate per-channel dials — an erase gate $\bm{b}^{(i)}$ and a write gate $\bm{w}^{(i)}$:

$$ e^{(i)}=\bm{b}^{(i)}\odot\kappa^{(i)},\quad z^{(i)}=\bm{w}^{(i)}\odot v^{(i)},\quad r_{\text{GDN2}}^{(i)}= z^{(i)} - \tilde{W}^{(i-1)} e^{(i)} $$
$$ W^{(i)} = \tilde{W}^{(i-1)} + r_{\text{GDN2}}^{(i)} \otimes \kappa^{(i)},\quad \tilde{W}^{(i-1)}=W^{(i-1)}D_{\alpha}^{(i)} $$

In plain words: $e$ decides which key channels to clear, $z$ decides which value rows to store, and the residual between them is what actually gets written. If $\bm{b}$ and $\bm{w}$ are both just $\beta$ everywhere, you get back Kimi; and if the vector decay is also uniform you get back Gated DeltaNet. It is a strict hierarchy.

More knobs = more precise editing, but not for free. Each extra gate needs learned weights, compute, and tuning. The paper later shows the most granular models are not always fastest — and speed is half the point of linear attention.

How do you feel the difference? Try the lab below. You are the janitor for a tiny 4 × 6 memory. An important pattern and several distractors take turns writing. Pick a gate type and watch the heatmap: scalar forgetting fades everything together, vector forgetting lets you keep right-side columns while clearing left-side ones, and split erase/write lets you erase one dimension and write another independently.

006Lesson 6 — What the experiments say~10 min

Faster or Smarter? You Can't Have Both For Free

Think of building a race car. You can make it lighter and faster, but you usually lose comfort and grip. You can make it grippier and smarter, but you add weight and it slows down. The paper found the same trade-off inside language models — no single design wins on both speed and smarts.

To make the comparison fair, they kept everything else the same: same 350-million-parameter size, same FineWeb-Edu text with the same tokenizer, same 4,096-token training chunks, same batch size, same bfloat16 precision on the same four GH200 GPUs. The only things that changed were the mixer — which flavor of attention — the stack pattern, and the optimizer.

Two stack patterns matter. Pure means every layer uses the fast linear memory. Hybrid means every third layer is still classic softmax attention — a 2-to-1 ratio of linear to softmax. That one softmax layer in three is like keeping one heavy but capable engine in an otherwise light car.

The results form a frontier, not a winner. Relative training speed is scaled so the fastest run — pure Gated DeltaNet with AdamW — is 100%. It is the quickest but its final validation loss (average surprise on held-out text, lower is better) is 2.433, quite high. At the other end, Kimi Delta Attention with Muon in a hybrid stack reaches the best loss in the whole 15B-token sweep, 2.273, but runs at only 70.9% speed. DeltaNet with Muon hybrid lands in the middle: 2.299 loss at 83.8% speed. Every matched pair in Table 2 shows Muon beating AdamW on loss — but Muon is a bit slower to run.

Hybrid buys accuracy back, but it costs you the very speed you wanted linear attention for. Pure keeps the speed. You pick based on your job: lowest loss at moderate length, or flattest cost at very long length.

The length test makes this concrete. From 4,096 to 32,768 tokens, softmax iteration time jumps about 2.9× to 3.37 seconds (+192%). The hybrid with one-third softmax layers jumps only 1.7× to 1.56 seconds (+65%). The pure linear stack barely moves: 1.1× to 0.96 seconds (+8%). The hybrid's extra cost is almost exactly one-third of softmax's — because one-third of its layers are softmax.

There is one more trap: learning rate. The paper trained hybrids for 2,000 steps at many rates and plotted the valleys. Muon likes around $3 \times 10^{-4}$, AdamW linear variants like around $10^{-3}$ (plain softmax is the exception at $3 \times 10^{-4}$). If you test both optimizers at the same single rate, one will look artificially bad. Try it yourself below — sweep the frontier and then slide the learning rate to see the winner flip.

007Lesson 7 — Passing notes across layers~9 min

Cross-Layer Notes — And Why the Error Note Didn't Help

Imagine a line of workers along an assembly line. Each one reads a long instruction stream and scribbles a quick note about what to remember. By the time the note reaches the end of the line, early clues have faded. Could a lower worker slip a note directly to a higher worker?

That's the idea behind cross-layer routing. Deep stacks can dilute useful signals from early layers — the paper notes prior fixes like Attention Residuals add explicit depth pathways, but those partly break the linear-time savings. This paper asks: can we reuse a signal the model already computes inside the Delta update, with no new quadratic attention, just a lightweight side-channel?

We track both depth and position as $(l,t)$ — layer $l$ and token position $t$. Only DeltaNet-style layers can write or read the note; the paper calls these "routing-capable" layers. If a softmax layer sits between two Delta layers, it just carries the note forward untouched, so the extra cost stays linear.

The first attempt is called Cross-Layer Error Residuals, or CLER. Recall from Lesson 4 that every Delta layer first predicts what its memory already thinks, $\bar{v}_{l,t}=W_{l,t-1}\kappa_{l,t}$, and computes the surprise $r_{l,t}=v_{l,t}-\bar{v}_{l,t}$. CLER forwards the surprise from the nearest lower routing layer $p(l)$ and adds it to the next layer's value target:

$$\tilde{v}_{l,t}=v_{l,t}+ \Gamma_{l}\,\rho\big(r_{p(l),t}\big)$$

Here $\Gamma_l$ is a single learned number per layer — how loudly to listen — and $\rho$ is just the identity in the main tests. The receiver then computes its own surprise against this nudged target:

$$r_{l,t}=\tilde{v}_{l,t}-W_{l,t-1}\kappa_{l,t}$$

Nothing else changes — same gates, same read rule $y=W\phi(q)$.

A real effect should beat noise. This paper treats a single-run difference smaller than about $0.001$ to $0.01$ in validation loss as not reliable — and Table 6 makes that point clearly.

And Table 6 is sobering. At 350M parameters and about 1B tokens, CLER does not help. With the Muon optimizer, CLER-Gated DeltaNet is $+0.0013$ worse than its matched baseline (2.8333 vs 2.8319), and CLER-DeltaNet is $-0.0004$ better — below what the authors count as meaningful. With AdamW it's flat or worse ($+0.0008$ and $+0.0190$). The note is definitely being sent — routed residuals are nonzero at every layer — but the matched loss curves sit almost on top of each other.

Why? The authors diagnose a space mismatch. The error $r_{p(l),t}$ is defined in one layer's private value space — its own learned projection of what matters. The upper layer has its own independently learned value space. Adding a correction written in the lower layer's dialect into the upper layer's inbox is often misaligned, so it competes with what the receiver actually wanted to write instead of helping.

008Lesson 8 — The winning tweak~10 min

Routing the Right Message in the Shared Hallway

Lesson 7 tried to let layers pass notes. It didn’t work. Each layer has its own private "value" dictionary — what value means in layer 5 is learned separately from what it means in layer 12. Forwarding layer 5’s error into layer 12’s value inbox was like slipping a correction written in one private shorthand into someone else’s notebook. The paper’s Table 6 showed it: that first try, called CLER, was active at every layer but barely moved validation loss (for example +0.0013 worse on Gated DeltaNet, −0.0004 on DeltaNet — both smaller than run-to-run noise).

This lesson is the fix. The authors changed two things at once.

1) A different hallway. Instead of injecting into the next layer’s private value target v, they inject into the shared hidden stream h — the main hallway every layer reads from and adds to. The new rule is simple:

$$\varepsilon_{l,t} = P_l \, s_{l,t} \qquad\text{and}\qquad h_{l,t} \leftarrow h_{l,t} + \varepsilon_{l,t}$$

Here s is the message to send, Pl is a small projection that turns it into hallway-size, and ε is what actually gets added. Pl is zero-initialized — all zeros at the start — so ε = 0 on day one. The model begins exactly as its baseline and only learns to use the hallway if it helps. Because h is shared across depth, the note stays aligned instead of getting misread.

2) A different message. In the hallway the authors could still send either the error r = v − v̄ (what memory failed to store) or the value v itself (what memory was trying to store, where v̄ = Wκ is what memory already predicted). Since v = r + v̄, the two messages live in the same space and use an identically-shaped Pl — the comparison is perfectly parameter-matched. Sending r into the hallway is called CLER-H; sending v is called CLVR (Cross-Layer Value Routing).

Value beat error, every time — but only by a little. That tells us the useful signal is the full target the lower layer wanted to remember, not just its correction. And we know it wasn’t just “more parameters”: routing the layer’s own hidden state instead gave Δ ≈ −0.0014, and simply enlarging the baseline made loss worse by +0.0021.

How big were the wins? The paper reports Δ versus a matched baseline (negative = better, all with Muon):

  • At 350M / 1B tokens: Gated DeltaNet CLVR −0.0103 vs CLER-H −0.0073; DeltaNet CLVR −0.0119 vs CLER-H −0.0047.
  • At 350M / 15B tokens: GDN −0.0059 vs −0.0042; DeltaNet −0.0016 vs −0.0002.
  • At 1.3B / 40B tokens (reported for GDN only): −0.0019 vs −0.0010.

Three takeaways: CLVR uniformly beats CLER-H; both are small; and both shrink as you train longer or go bigger — a stronger base memory leaves less for cross-layer help to add. Fancier variants like surprise-gating the value or sending both [r;v] didn’t beat plain value, and Attention Residuals (a different depth-attention trick) helped DeltaNet (−0.0101) but hurt GDN (+0.0030).

Where does this leave the big picture? There is still no single winner — it’s a frontier. In the paper’s 350M/15B sweep the best absolute loss is still Kimi Delta Attention + Muon in a hybrid stack at 2.273; the fastest is pure Gated DeltaNet + AdamW at 100% relative speed. CLVR is a lightweight, linear-time extra that doesn’t change that frontier much, and the paper didn’t test it on Kimi or Gated DeltaNet-2, didn’t run it on long-context recall tasks, and didn’t benchmark inference. Those are the open questions.

ABCWord bank

Word bank.

softmax attention

The standard way transformers let each token look at all previous tokens. It computes a similarity score between a query and every previous key with an exponential (exp), normalizes them to sum to 1, and uses those weights to average previous values.

linear attention

A faster alternative that replaces the exponential with a feature map decomposition: exp(q·k) ≈ φ(q)·φ(k). This lets the model keep a running sum instead of comparing every pair.

feature map φ(k)

A function φ that transforms keys and queries into a new space where dot products are cheap to accumulate. Example: φ(x)=ELU(x)+1.

recurrent memory W

A matrix W (size d_v × d_φ) that stores all previous key-value pairs as a running sum: W⁽ⁱ⁾ = sum v⁽ʲ⁾⊗φ(k⁽ʲ⁾). Reading is one matrix-vector product: y⁽ⁱ⁾ = W⁽ⁱ⁾ φ(q⁽ⁱ⁾).

Q, K, V

Query, Key, Value — three vectors made from each token's representation. The query asks 'what do I need?', the key labels 'what I contain', the value is the content to retrieve.

memory prediction v̄

The model's prediction from memory before seeing the true value: v̄⁽ⁱ⁾ = W⁽ⁱ⁻¹⁾ κ⁽ⁱ⁾ where κ⁽ⁱ⁾=φ(k⁽ⁱ⁾).

residual / delta-rule error r

The error between what you want to store and what memory already predicts: r⁽ⁱ⁾ = v⁽ⁱ⁾ − v̄⁽ⁱ⁾. DeltaNet writes only this correction.

delta rule

The update rule W⁽ⁱ⁾ = W⁽ⁱ⁻¹⁾ + β r⊗κ, where β in (0,1) controls write strength. It rewrites rather than blindly adds.

gate (α, β, b, w)

A learned number between 0 and 1 that decides how much old memory to keep. 1 = keep everything, 0 = forget everything.

scalar decay (Gated DeltaNet)

Forgetting the whole memory by the same factor α: W = α W_prev + ...

channel-wise decay (Kimi Delta Attention)

Forgetting each feature channel at its own rate with a vector α and diagonal matrix D_α: W D_α. Lets the model keep some subspaces while clearing others.

decoupled erase/write (Gated DeltaNet-2)

Splitting the write into two separate gates: b (erase which key-channels to clear) and w (write which value-channels to store). Most fine-grained control.

hybrid vs pure stack

Stacking layers where every 3rd layer is softmax and 2 are linear (2:1 pattern). Pure = all linear, dense = all softmax.

validation loss

Average surprise of the model on held-out text, measured as cross-entropy. Lower is better. Paper's main quality metric.

relative speed / throughput

Training tokens processed per second. Paper normalizes pure Gated DeltaNet+AdamW to 100%. Not inference speed.

CLER (Cross-Layer Error Residuals)

First attempt to share across depth: forward a lower layer's write error r into the next routing-capable layer's value target: ṽ = v + Γ·r.

CLVR (Cross-Layer Value Routing)

Improved method: forward the write value v (not the error) into the shared hidden stream h via a zero-initialized projection P: h ← h + P·s, where s=v. Preserves linear time.

residual stream / hidden stream h

The main hallway of the transformer that every layer reads from and adds to. Adding there reaches all later layers, unlike a private per-layer value space.

Muon vs AdamW

Two optimizers tested. Muon consistently gave lower final loss than AdamW in matched 350M/15B runs, but prefers lower learning rate ~3e-4 vs AdamW ~1e-3.
