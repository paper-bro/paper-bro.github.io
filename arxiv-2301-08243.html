001Two old ways fail~8 min

Why Teach Computers Without Labels?

Imagine you have a million unlabeled photos and no time to label a single dog or car. Can a computer still learn what those mean? That is self-supervised learning: the computer invents its own puzzle from the raw images, solves it, and gets smarter — with no human labels at all.

For years there were two main puzzles. Think of them as two teachers with opposite flaws.

🪞

Teacher 1: “Be blind to my tricks”

Invariance-based methods like DINO, iBOT and MSN take one photo, make two hand-crafted views with random cropping, color jitter and blurring, and train two encoders to output the same list of numbers (embedding) for both views. The model learns to ignore color and cropping. It becomes quite semantic, but it is biased: you told it what to forget, and those photo tricks do not exist for sound or text, so they do not generalize.

🧩

Teacher 2: “Copy every pixel”

Generative methods like MAE, BEiT and SimMIM cut out random little patches and say: reconstruct the exact missing pixels. This needs no hand-made color tricks, so it works for many kinds of data. But it is like forcing a student to memorize wallpaper. A huge MAE ViT-H/14 trained for 1600 epochs got only 77.2% on ImageNet linear probing — it learned textures, not ideas.

One teacher forces forgetting, the other forces photocopying. Neither asks: what is the meaning in the missing part?

The I-JEPA idea: hide big, meaningful chunks and predict ideas, not pixels. From one visible context block, predict the representations (idea-vectors) of several hidden target blocks from the same image. The loss is in embedding space, so irrelevant texture can be ignored.

An embedding is just a list of numbers that summarizes “what is there” — pose, shape, object parts — while dropping background speckles. You judge it off-the-shelf by freezing the encoder and training only a tiny linear classifier on top (linear probing). If that scores well, the frozen ideas were already semantic.

I-JEPA with the same ViT-H/14 reached 79.3% in only 300 epochs — better meaning, about 5 times fewer training steps, and with no color-jitter views at all. Instead of telling the model what to forget, it learns what to keep.

Try it below: toggle between the two old teachers. Slide the strength up and watch what each is forced to ignore or memorize — and why both struggle before we fix it.

002The puzzle pieces~7 min

How Computers See Pictures as Puzzles

Imagine cutting a photo into tiny squares like a jigsaw puzzle. That's exactly how the AI in the paper sees. It doesn't see a “dog” all at once — it sees hundreds of little patches, turns each one into a list of numbers, and then lets the patches talk to each other.

Formally, the input image is called $y$. The model cuts $y$ into $N$ non-overlapping patches. With the ViT-H/14 model the paper uses, each patch is $14 \times 14$ pixels. On a $224 \times 224$ image that means $224/14 = 16$ patches across and $16$ down, so $N = 16 \times 16 = 256$ patches. Each patch is turned into a vector — the paper calls this an embedding — and a Vision Transformer (ViT) runs self-attention and MLP layers to let every patch see context from the others.

After the transformer, you get a patch-level representation the paper writes as $s_y = \{s_{y1}, \dots, s_{yN}\}$. That just means: one vector $s_{y_k}$ for each of the $N$ patch positions $k$. If a patch shows an eye, its vector will be different from a patch showing sky, but all $N$ vectors together describe the whole image.

🧩

Patches are the units

Smaller patch size = more pieces. $14$px gives $256$ tokens; $16$px gives $196$; $8$px gives $784$. More tokens means finer detail but more work.

🧠

Vectors are the meaning

Each patch vector is not color, it's a learned summary — pose, texture, part identity — sized $384$ to $1408$ numbers depending on the ViT size.

To answer “what is in the photo?” the model needs one global summary. Older ViTs add a special extra token called [CLS] — like an elected spokesperson. I-JEPA does not use that. It simply average-pools: it adds up all $N$ patch vectors and divides by $N$. That average is used as the global image vector for downstream tasks like linear probing, where a single linear layer is trained on top of the frozen features.

Thinking in patches also makes the paper's trick possible. You can hide information in two very different places. You can mask the input before the encoder ever sees it — that's what the context block does. Or you can run the encoder on the full image first, and then mask its output vectors $s_y$. I-JEPA does the second for its targets: it gets semantic target vectors by masking the output of a target-encoder, not the pixels. That choice is why the targets are ideas, not colors — a point the next lesson digs into in detail.

The paper goes further with many ViT sizes (B/16, L/16, H/14, G/16) and different image resolutions, but the core stays the same: cut, embed, attend, then pool.

003Ideas, not pixels~9 min

Predicting Ideas, Not Pixels

Imagine two ways to learn from a photo with a hidden patch. One student must repaint the missing pixels exactly — every shadow, every speck of texture. The other student just has to describe the idea: "there's a bird's back, facing left." Which student will learn what a bird is?

The paper argues the second student learns better. Reconstructing pixels forces a model to waste effort on irrelevant details like precise texture and background. Predicting ideas lets it throw that detail away and keep shape, pose, and object identity.

I-JEPA makes this concrete. It runs the whole image through a learned target-encoder — a Vision Transformer called $f_{\bar{\theta}}$ — to get a representation for every patch, ${\bm s}_y = \{{\bm s}_{y_1},\dots,{\bm s}_{y_N}\}$. Think of each ${\bm s}_{y_j}$ as a little "idea vector" for patch $j$, not a patch of colors. It also encodes the visible context block with a context-encoder $f_\theta$ to get ${\bm s}_x$.

Then a small predictor $g_\phi$ tries to guess the missing idea vectors from the context ideas plus a clue about where to look. That clue is a mask token ${\bm m}_j$ — a shared learnable vector plus a position code that says "predict the patch at this location." For each of $M$ target blocks $B_i$, it predicts $\hat{\bm s}_y(i)=g_\phi({\bm s}_x,\{{\bm m}_j\}_{j\in B_i})$.

$$\frac{1}{M}\sum_{i=1}^{M}\sum_{j\in B_i}\left\lVert \hat{\bm s}_{y_j} - {\bm s}_{y_j}\right\rVert_2^2$$

In plain words: for each target block ($M$ is usually 4), for each patch $j$ inside that block, measure the squared distance — the $L_2$ distance — between the predicted idea $\hat{\bm s}_{y_j}$ and the true idea ${\bm s}_{y_j}$ from the target-encoder. Average over all $M$ blocks. That's the whole loss. No pixels. The predictor and context-encoder learn to make this number small; the target-encoder is updated slowly as an average of the context-encoder, so it produces stable, increasingly abstract targets.

Why it matters: learned targets can forget. A pixel target can't forget — it is fixed RGB values. A representation target is learned during training, so it is free to drop texture and keep meaning. That's why the same ViT-L/16 trained on only 1% of ImageNet labels scores 66.9% when predicting representations, but collapses to 40.7% when forced to predict pixels (Table 7) — a 26-point gap.

004Hide the right pieces~10 min

The Art of Hiding the Right Pieces

Imagine you hide pieces of a photo for a friend to guess. If you hide single scattered pixels, your friend just copies nearby colors — no real understanding needed. If you hide one giant half of the image, there is often nothing left to guess from. The I-JEPA trick is hiding the right pieces.

The paper turns an image into $N$ patches — for example $224/14 = 16$ patches per side, so $N = 256$. Then it samples:

  • Targets: $M = 4$ blocks — each with a random size covering $0.15$ to $0.20$ of the image area (about $15\%$ to $20\%$) and a random stretch (aspect ratio $0.75$ to $1.5$). That is big enough to hold a meaningful part, like an ear, wheel, or wing, not just texture. The four blocks may even overlap each other at first.
  • Context: $1$ huge block — size $0.85$ to $1.0$ of the image, with square shape (aspect $1.0$). Then the system deletes any overlap with the four targets. What remains is sparse and scattered — on average only about $0.25$ of all patches (about $1$ in $4$) stay visible — but it is spread across the image, so it is still informative.
Why this matters: big semantic targets force the model to predict ideas (shape, pose, object part) instead of low-level pixels. A large, distributed context keeps the task solvable, while sparsity keeps it cheap — the encoder only processes visible patches, like MAE.

How do we know it matters? Table 6 trains the same small ViT-B/16 for 300 epochs and tests with only $1\%$ of ImageNet labels (a frozen linear probe):

  • Multi-block (paper): 54.2% — four semantic blocks as above.
  • Single big block (scale $0.6$, rest is context): 20.2%
  • Random scattered patches as target: 17.6%
  • Rasterized: split into 4 quadrants, predict 3 from 1: 15.5%

Same model, same compute — just changing what you hide cuts accuracy by more than half. And size matters both ways:

  • Targets too small ($0.075$ to $0.2$ scale) → drops to 19.2% (Table 8). The model just learns texture.
  • Context too small ($0.40$ to $1.0$ scale instead of $0.85$ to $1.0$) → drops to 31.2% (Table 9). Too little clue to predict meaning.
  • Using only $1$ target instead of $4$ → 9.0% vs 54.2% with $4$ (Table 10). More diverse predictions teach richer ideas.
Said with numbers: paper section 3 writes targets as $s_y(i)=\{s_{y_j}\}_{j\in B_i}$ where $B_i$ is the patch-index mask for the $i$-th target, and context as $s_x=\{s_{x_j}\}_{j\in B_x}$ with $B_x$ the context mask. Overlap removal is simply $B_x \leftarrow B_x \setminus \bigcup_i B_i$.

005Encoder, target, predictor~9 min

Two Encoders and a Mind-Reading Predictor

Think of a detective game. One friend sees only a corner of a photo. Another friend secretly sees the whole photo but whispers just the idea of what’s in the hidden corners — not the exact pixels. The first friend must guess that idea, given a note that says where to guess.

I-JEPA builds this game with three networks that work together.

👁️

Context encoder $f_\theta$

Standard ViT (ViT-B/16, L/16, H/14, G/16). It only sees the visible context patches — about 25% of the image on average — so it’s fast. Output: patch vectors $s_x = \{s_{x_j}\}_{j \in B_x}$.

🪞

Target encoder $f_{\bar\theta}$

Same ViT shape, but sees the full image. We mask its output $s_y = \{s_{y_j}\}$ to carve out targets $s_y(i)=\{s_{y_j}\}_{j\in B_i}$. No gradient ever flows through it.

🧠

Predictor $g_\phi$

Narrow ViT that takes $s_x$ plus special mask tokens $\{m_j\}_{j\in B_i}$ that encode position. It outputs $\hat s_y(i)=g_\phi(s_x,\{m_j\})$ separately for each of $M=4$ target blocks.

Why two encoders? If the same network made both the guess and the answer and learned from its own gradient, it could cheat by making every image map to the same constant vector — collapse. I-JEPA avoids this with asymmetry: the target encoder $f_{\bar\theta}$ is not trained directly. It starts equal to the context encoder and then slowly tracks it with an exponential moving average (EMA): each step $\bar\theta \leftarrow \text{momentum}\cdot \bar\theta + (1-\text{momentum})\cdot \theta$, with momentum 0.996 growing linearly to 1.0 during training. It’s a stable, slowly-updating teacher.

Why mask the output of the target encoder, not its input? The target encoder sees the whole image, so its vectors already mix information from neighboring patches — they are more semantic. If you mask the image first and run the encoder once per block, you get a narrow view and lower quality. The paper shows this clearly: masking the output gives 67.3% on 1% ImageNet linear (ViT-H/16, 300 epochs), masking the input only 56.1% — a big drop in Table 11.

The predictor knows where to predict because each mask token $m_j$ is a shared learnable vector plus a positional embedding for patch $j$. Same predictor runs $M$ times, once per target location.

Why is the predictor narrow? For ViT-L the encoder is 1024-wide; the predictor is fixed to width 384 — a bottleneck. Depth is 6 for ViT-B, 12 for ViT-L/H, and 16 for ViT-G. This forces the predictor to be small and general, not memorize. Appendix C shows it helps: depth 12 beats depth 6 (66.9% vs 64.0% Table 12) and width 384 beats 1024 (70.7% vs 68.4% fine-tune on 1% ImageNet Table 14).

006What is remembered?~8 min

What Does the Machine Actually Remember?

An I-JEPA model never learns to paint pixels. It learns to predict ideas — numbers that describe what is in a patch. But what ideas does it actually keep? To see inside, the authors froze the trained model and attached a separate image generator that can read its thoughts.

Here is the trick, called RCDM. You train a small diffusion decoder to do one job: given a frozen representation — the average-pooled output of the encoder or of the predictor — plus a noisy image, recreate the original image. Once trained, you feed it the same representation with different random noise and generate several pictures.

A simple rule lets you read the result: what stays the same across all samples was inside the representation; what changes was thrown away. If every sample shows a bird facing left, pose was remembered. If one sample is red, another blue, color was forgotten.

I-JEPA predictor — conditioned on a green box position — draws the right object part in the right pose inside that box, like the back of a bird or the top of a car. I-JEPA encoder keeps pose, scale, and how many objects there are, but forgets exact texture and background.

Compare that to MSN, a method that learns by forcing different hand-made views of the same image to match. Its representations also look semantic at first glance, but when you decode them, the samples wobble: a bird turns around, one dog becomes two, a car changes size. MSN threw away the local layout that I-JEPA kept.

Both models are smart to discard something. You do not need the exact leaf pattern behind the bird to know it is a bird. I-JEPA learns to keep the high-level shape and where things are, and to ignore pixel-perfect detail.

In the lab, try it yourself. Pick a pose, count, color, and background for the original. Then decode the same frozen feature five times. With I-JEPA selected, watch pose and count stay locked while color and background scramble. Flip to MSN and watch even pose and count fall apart — just like Figures 7 and 8 in the paper.

007Scores and speed~9 min

How Well Does It Work? Speed, Scale, and Scores

So does predicting ideas actually help? On ImageNet — the standard big test with 1,000 kinds of objects — the answer is a strong yes, and fast.

First, the quality test. Freeze the encoder after pretraining and train only one tiny linear layer on top. This is called linear probing: if the frozen features are already semantic, a simple layer is enough. The paper reports:

  • ViT-B/16: I-JEPA 72.9% in 600 epochs beats MAE 68.0% in 1,600 epochs.
  • ViT-L/16: I-JEPA 77.5% beats MAE 76.0%.
  • ViT-H/14: I-JEPA 79.3% in only 300 epochs beats MAE 77.2% in 1,600 epochs.
  • ViT-H/16 at 448×448 pixels: I-JEPA 81.1% in 300 epochs — without any hand-crafted views — matches iBOT 81.0% with views.

That last line matters. iBOT, DINO and similar winners rely on humans inventing two different augmented views (random crop, color jitter) of the same image and forcing the embeddings to match. I-JEPA never uses those tricks during pretraining. It still ties them on the semantic task.

Scarce labels: with only 1% of ImageNet labels (about 13 images per class), I-JEPA ViT-H/14 gets 73.3% — same as data2vec ViT-L but cheaper to train. At higher resolution (448), it reaches 77.3%, beating MSN 75.7%, DINO 70.0% and iBOT 69.7%. So the features are useful even when you have almost no labels.

Transfer is similar. Put that same frozen encoder on a new dataset: CIFAR100 87.5% vs MAE 77.3% (+10.2), Places205 58.4% vs 55.0%. On iNat18 it jumps from 32.9% (MAE) to 47.6%.

The surprise is on low-level tasks. On Clevr depth prediction (Clevr/Dist), a frozen linear probe must guess how far objects are. View-invariant methods were taught to ignore geometry to make two crops match, so they suffer: DINO 53.4%, iBOT 62.8%. I-JEPA, which was never forced to be invariant, keeps local shape: 72.4% — tied with MAE and far ahead of the view-invariant models. On counting (Clevr/Count) it is 86.7%, competitive with the best.

Speed and scale: the paper trained ViT-H/14 on ImageNet in under 72 hours on 16 A100 GPUs — less than 1,200 GPU-hours total. Per training step I-JEPA is about 7% slower than MAE (because it also runs a target encoder in representation space), but it converges in roughly 5× fewer steps. Net result: over 2.5× faster than the smallest iBOT model (ViT-S/16) and over 10× more efficient than MAE ViT-H/14. Bigger data (ImageNet-22K) and bigger models (ViT-G/16) help further, e.g., Places205 57.8 → 59.1 and iNat18 50.5 → 55.3.

In short: I-JEPA learns both what something is and where it is, without view tricks, and does it on a realistic compute budget.

008What matters most?~8 min

What Matters Most? Testing Every Choice

Scientists don't just try one recipe — they test every ingredient. The I-JEPA team asked: is predicting ideas really better than predicting pixels? Does it matter where you hide? Does the predictor need to be narrow? And do you need many hidden blocks?

First, the target. Same model, two ways to learn. If the loss tries to copy exact pixels, the 1% ImageNet score collapses to 40.7%. If the loss predicts learned representations — vectors from a teacher that has already thrown away texture — it jumps to 66.9% (Table 7). In plain words, the teacher decides what counts as an idea, and the learner only learns those ideas.

Second, where you make targets. I-JEPA runs its target-teacher on the whole image, then cuts out blocks from the teacher's output. That gives semantic targets that saw the full picture. If you instead cut holes in the image first and run the teacher on each little hole separately, you drop from 67.3% to 56.1% (Table 11) — and you also have to run the teacher many times, so it's slower.

Third, the predictor — the little mind-reader that takes what you saw plus position tokens and guesses a hidden block. Making it a bottleneck helps. A narrow predictor (width 384 instead of 1024, while the encoder is 1024) does better on 1% fine-tuning: 70.7% vs 68.4% (Table 14). A deeper predictor (12 layers instead of 6) does better on 1% linear: 66.9% vs 64.0% (Table 12). Why? A bottleneck forces it to actually use the context, not memorize.

Why EMA and asymmetry? If the context and target encoders were the same and trained together, they could both cheat by outputting the same constant for every image — collapse. I-JEPA breaks the symmetry: only the context encoder gets gradients; the target encoder slowly follows it with an exponential moving average (momentum 0.996 → 1.0) and never gets a direct gradient. Nothing to cheat with.

Fourth, how many hidden blocks? Predicting 4 fairly large semantic blocks scores 54.2% (ViT-B/16, 300 epochs, 1%). With 3 it's 48.5%, with 2 it's 22.0%, with 1 it's only 9.0% (Table 10). More varied “what's over there?” questions teach more.

Finally, scale. The same I-JEPA idea gets better with more data and bigger brains — without ever needing hand-made color tricks. For ViT-H/14, training on ImageNet-22K instead of ImageNet-1K lifts Clevr/Dist 72.4 → 75.0 and iNat18 47.6 → 50.5, but Places205 slightly decreases 58.4 → 57.8 (Table 5). Training a larger ViT-G/16 on IN-22K then lifts Places205 57.8 → 59.1 and iNat18 50.5 → 55.3. No view augmentations, yet it matches the best view-based methods and keeps local detail.

Now try it: flip each switch in the lab from the good recipe to the bad alternative — pixels, masking the input, wide/shallow predictor, fewer targets — and watch the exact drop the paper measured. Which single choice hurts most?

ABCWord bank

Word bank.

Self-supervised learning

Learning without human labels. The model creates its own puzzle from unlabeled images (like hiding parts) and learns by solving it.

Representation / Embedding

A list of numbers the computer uses to describe an image or patch. Think of it as a summary that keeps the meaning but forgets irrelevant details.

Vision Transformer (ViT)

A Vision Transformer. It cuts an image into small non-overlapping squares called patches (e.g., 14x14 pixels), turns each into a token, and lets them talk to each other with self-attention.

Block

A block of pixels (like a puzzle piece) the model either sees as context or has to predict as a target.

L2 prediction loss

In I-JEPA, the average squared distance between predicted and true patch representations: 1/M * sum_i sum_j ||hat_s_{y_j} - s_{y_j}||^2. The model tries to make this as small as possible.

Exponential Moving Average (EMA)

A network that slowly copies another network's weights. Target-encoder weights start equal to the context-encoder, then are updated with momentum 0.996 growing to 1.0, without ever getting direct gradient updates.

Linear probing

Testing what the model learned by freezing it and training only a tiny simple classifier (one linear layer) on top. If it scores well, the frozen features were already semantic.

Fine-tuning

Training the pretrained model further on labeled data, updating all its weights. Stronger but more expensive than linear probing.

Hand-crafted data augmentation

Human-designed image tricks to make two views of the same image, like random cropping, color jitter, or flipping. Previous top methods needed them; I-JEPA does not.

Collapse

Representation collapse: when an encoder learns to output the same boring constant vector for every image to cheat the loss. I-JEPA avoids it with an asymmetric target-encoder updated by EMA.

Predictor

A small Transformer that takes the context features plus special mask tokens that encode position (where to predict) and outputs the predicted target representations for that location.
