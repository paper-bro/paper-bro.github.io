001Lesson 1~8 min

When a private estimate is forced to be useless

Imagine you collect data from many people, and you want to publish a simple pattern — say, the average ear length, or the main direction a cloud of points stretches. You also promise privacy: if one person had stayed home, your published answer would look almost the same.

The problem is that the promise has to hold for any possible dataset, even a crazy one you never actually saw. To keep it, most private methods add random noise. How much? Enough to hide the biggest change one record could cause in the worst case. That is called global sensitivity.

The paper's running example makes this painful. The task is to find the $k$-dimensional subspace where Gaussian data in $d$ dimensions vary most — its top $k$ eigenvectors. Think of a thin pancake of points in 3D and you want the flat plane it lies in.

On typical data for this task, the points already cluster near that plane. A non-private estimate is good with a number of samples that grows with $k$ (the pancake's own dimension) but not with $d$ (the big room it sits in). Remove one typical point and the estimated plane barely wiggles. The paper calls that wiggle the local sensitivity — the biggest change from this dataset.

One weird record can force useless noise — even when your actual data is perfectly well-behaved. That gap between global (worst-case) and local (this dataset) is what the paper wants to close.

But privacy must also protect the weird record. A single huge point pointing straight out of the pancake can swing the empirical plane by 90 degrees, no matter how many normal points you have. So global sensitivity is maximal. A naive private fix clips every point to a public size, builds the $d \times d$ second-moment matrix, and adds noise big enough to hide any one clipped point. That noise grows with $d$, not with the pancake's thin spread, so you need polynomially many more samples — exactly the dependence the non-private method avoided.

You might think: just add noise sized to the small local sensitivity on typical data. That fails too. The scale of the noise would then depend on the data, and that scale itself leaks information about who is in the data.

So we need a method whose noise looks like it matches the typical, well-clustered data, while still being private on every input — even the weird ones, where it is allowed to just give up. The next lab lets you feel that tension: one outlier dictates global noise, local noise is tiny, and neither alone solves privacy.

Try it: drag the red outlier close to the cloud, then far away. Toggle between noise sized to global vs local sensitivity. Watch how the green non-private line barely moves, but the purple private line jumps wildly under global noise — and why local noise, while accurate, would leak.

002Lesson 2~8 min

A precise promise: one person barely matters

The paper wants a very strong promise: even if I know everything about the dataset except one person, seeing the output should barely help me guess what that last person did. Making that promise precise is what lets the rest of the paper work.

First, how do we describe "one person's change"? The paper uses zero-out adjacency. Think of a dataset as a row of $n$ slots. Two datasets $s$ and $s^{i\to\bot}$ are neighbors, written $s \simeq s'$, if they are identical except slot $i$ becomes $\bot$ — a null placeholder that means "this person stayed home".

Why keep the slot? Then every dataset has the same $n$, the same number of reference blocks $m=n/b$ later, and null records are counted in averages but never count as friendly. Replacing Alice's record with Bob's is just two zero-out steps through $\bot$, so it costs at most twice the privacy budget.

What the promise means: an algorithm $M$ is $(\varepsilon,\delta)$-DP if for every neighboring pair $s \simeq s'$ and every event $O$ about the output,
$$\Pr[M(s)\in O] \le e^{\varepsilon}\Pr[M(s')\in O] + \delta$$ and the same with $s$ and $s'$ swapped. Smaller $\varepsilon$ means the two distributions overlap more — at $\varepsilon=0$ they are identical. $\delta$ is a tiny extra allowance, like $10^{-6}$, for a freak failure.

How do we get that overlap? Add noise scaled to how much one person can change the answer — the sensitivity. If a query $q$ changes by at most $1$ on any neighbors, adding Laplace noise of scale $\sigma$,

$$M(s)=q(s)+\operatorname{Lap}(\sigma)$$

is $(1/\sigma,0)$-DP. That is, $\varepsilon =1/\sigma$. Bigger $\sigma$ → smaller $\varepsilon$ → more private. For Gaussian noise $\mathcal{N}(0,\sigma^2)$ the guarantee is a curve, not one number:

$$\delta_{\mathcal{N}_\sigma}(\varepsilon)=\Phi\!\left(\frac{1}{2\sigma}-\varepsilon\sigma\right)-e^{\varepsilon}\Phi\!\left(-\frac{1}{2\sigma}-\varepsilon\sigma\right)$$

where $\Phi$ is the standard bell-curve tail. You pick $\sigma$ so this $\delta$ is small enough, typically $\sigma \approx \sqrt{\ln(1/\delta)}/\varepsilon$.

Doing private steps in a row costs more. If you run $N$ steps each $(\zeta,0)$-DP, advanced composition says the whole thing is about $(\varepsilon_{\text{comp}},\delta_0)$-DP with

$$\varepsilon_{\text{comp}} = N\zeta^2/2 + \zeta\sqrt{2N\ln(1/\delta_0)}$$

— much better than $N\zeta$ when $\zeta$ is small. And if you run a filter first and a release after, two-stage composition just adds the budgets: $(\varepsilon_1+\varepsilon_2,\delta_1+\delta_2)$.

Why not just add noise sized to how wobbly this dataset is — its local sensitivity? Because the size of the noise would then depend on the data, and that dependence leaks. A dataset that happens to need tiny noise reveals "I'm stable", which itself is information about its records. The paper has to make the noise scale public, while still letting the typical small sensitivity win.

Try it below: two datasets differ by one person (43 vs 44 "yes" answers). Move $\varepsilon$ and watch how the histograms of $500$ noisy answers go from almost identical to clearly separated. Notice how $e^{\varepsilon}$ controls the allowed ratio of probabilities — that's the promise in action.

003Lesson 3~10 min

Checking everyone at once throws away good data

Imagine you promised to shout “FAIL, I can’t answer safely” whenever your data is close to breaking a safety rule. That’s the idea behind an earlier fix called Propose-Test-Release, or PTR.

You propose a bound like “no single record moves my estimate more than τ,” then you test how many record-changes you are from data that would break that bound. That number is called distτ(s) — the distance from your dataset s to a violating one. If that distance is small, you add a little Laplace noise and abort. If it’s large, you run your normal noisy estimate.

This works when violating data is rare and far away. It fails when a violation is always next door.

Why PTR always rings the alarm here: Scores like leverage — how much a vector stretches the shape of the data — or the trace score from the next lesson are unbounded. For any dataset s, you can invent one extra record big enough to blow past any τ you proposed. That means distτ(s) ≤ 1 for every s. The paper proves (Proposition C.5) PTR then returns FAIL on every input, except with tiny probability at most eε0δ0/2. One hypothetical bad person dooms the whole dataset, even if all your real records are perfectly typical.

A second earlier fix tried a different angle: don’t judge the whole dataset, judge records by who their friends are. That’s FriendlyCore.

FriendlyCore picks a friendship rule ψ(x,y) — for example “friends if distance < r.” It counts, for each record, how many friends it has, keeps the popular ones, and throws out the loners. The release step then only needs to be private when the kept records are pairwise compatible — roughly, every two kept records share a common friend.

For a round clump of points, this is perfect: good points crowd together and have many friends, outliers sit far away and have few. But for a subspace — a long flat cloud — distance points the wrong way. Picture data stretched along a line:

📏

Probe A: far along the line

Both probes sit on the true subspace, but they are far from each other. By distance they look like strangers, so each has few friends — even though both are excellent.

🎯

Probe B: off the line, near the origin

This probe is the bad one — it sticks out across the subspace. But it sits near the middle of the cloud, so it is close to many records and looks very popular.

This is Figure 2a from the paper. Two good points can be declared “not friends” while a bad point near the center collects many friends. Friendship by Euclidean distance misses what actually matters: influence on the estimated subspace.

PTR fails because it tests everyone at once. FriendlyCore fails here because it tests pairs with the wrong ruler.

The lab lets you feel both failures. First, watch PTR’s distance meter stay stuck at ≤1 no matter how nice your data is. Then switch to FriendlyCore and slide the friendship radius — see the good points on the line lose friends while the off-line bad point keeps them, and check how a tight clump makes the same radius work fine. The next lesson shows how the paper fixes this with a per-record filter that judges each person against whole blocks of data, not against single neighbors.

004Lesson 4~10 min

Filter first, then release

Imagine a club where one unruly guest could make you think the whole crowd is unruly. Earlier private methods do exactly that: they check the entire dataset at once against a proposed safety limit. If the dataset is close to even one bad record, they give up on everything.

Propose-Filter-Release (PFR) instead hires a private bouncer. The bouncer looks at each person individually, quietly nulls (replaces by ⊥) the few who don't fit the rest, and then lets the party — the release mechanism — run on who remains. A single odd record no longer cancels the whole dataset.

The PFR theorem turns a conditional privacy promise into a universal one. You supply a filter and a release that are only private when a record fits. PFR proves the combination is private on every input, even inputs full of outliers.

The three ingredients

1. A jointly-private filter F. F(s) keeps each slot but may replace some records by ⊥. It is (ε₁,δ₁)-JDP — jointly differentially private — meaning: take neighbors s and s^{i→⊥} (same n slots, slot i nulled). After filtering and then nulling slot i in both outputs, the two filtered datasets look almost the same. Formally F(s)^{i→⊥} ≈_{ε₁,δ₁} F(s^{i→⊥}). The filter may reveal whether it kept sᵢ, but nothing much else.

2. A friendly release M. M only has to be private when the changed record fits the rest. We write F(s^{i→⊥}, sᵢ)=1 for "sᵢ is friendly with the rest" (defined by a score threshold). Then M is (ε₂,δ₂)-friendly-DP: M(s^{i→⊥}) ≈_{ε₂,δ₂} M(s) whenever friendliness holds. Outliers are the filter's job, not M's.

3. Establishment. The filter must actually make the changed record friendly, with high probability. For each slot i, the chance that F(s) keeps sᵢ yet it is not friendly with the rest of the filtered data is at most δ₃. That is Pr[ kept and F(F(s)^{i→⊥},sᵢ)=0 ] ≤ δ₃.

$$M\circ F \text{ is }(\varepsilon_1+\varepsilon_2,\; \delta_1+\delta_2+e^{\varepsilon_1+\varepsilon_2}\delta_3)\text{-DP on every }s$$

This is Theorem 4.4, in simplified form. Each part of the ε budget adds: filter plus release. Each part of the δ budget adds too, and the small establishment failure δ₃ is multiplied by e^{ε₁+ε₂} because we may pay for it in the worst direction. If the filter never keeps an unfriendly record, δ₃=0.

🔍

Testing (PTR)

Asks: "Is the whole dataset far from any violation?" One possible huge record anywhere makes the answer "no," so PTR returns FAIL for all inputs for unbounded scores (Prop. C.5).

🧹

Filtering (PFR)

Asks per record: "Is this record friendly with the remaining filtered data?" One bad record is removed; the other n-1 survive. Tolerates up to about 12·L/ε outliers where L=ln(16/δ), not a constant fraction.

If too many records fail — more than a noisy cap K̃ = ⌈2σ₁L + Lap(σ₁)⌉ — the filter aborts and returns ⊥ⁿ (all nulls). PFR then simply outputs M(⊥ⁿ) without announcing the abort, so even aborting leaks nothing. Privacy holds always; usefulness depends on keeping most data, which later lessons prove for typical data. FriendlyCore is one concrete bouncer that fits this same interface, with a different friendliness rule (pairwise friends).

In the lab below, build a dataset with a few outliers. Move the sliders for ε₁ and ε₂ to split the privacy budget and watch the final (ε,δ) add up. Change δ to see L and the cap K̃ grow, and compare: PTR fails the whole dataset as soon as one outlier appears, while the PFR filter removes only that record — until the cap is hit, when it privately aborts.

005Lesson 5~12 min

Ask many blocks, combine with math

Last lesson gave you the deal: a filter that is privately stable plus a release that is private for "friendly" records makes the whole thing private. Now we open the filter and see how it works — without ever looking at the records' actual values.

The new filter is called element–block filtering. First it shuffles the n slots into m = n/b reference blocks of size b each, uniformly at random. Think of each block as a mini-committee that knows what normal looks like.

For every record i it counts friends:

$$c_i = \#\{\text{blocks } s^{(j)} : \varphi(s^{(j)}, s_i) \ge 2\tau\}$$

where φ is the application's friendliness score and 2τ is a stricter threshold than the release needs. A high score means "you fit well", so this asks "how many committees would vouch for you?" It keeps the record only if a noisy count clears a high bar:

$$\text{keep } s_i \text{ if } c_i + \text{Lap}(\sigma_m) > t,\ \text{with } t = 7m/8$$

Lap(σm) is fresh Laplace noise of scale σm. Why noise? Changing one record changes one block, so every other count c_j shifts by at most 1 — sensitivity 1. But the test of the changed record itself can flip arbitrarily, because it asks about a different record entirely. Adding independent noise to each test and paying privacy only for the K ≈ 24L/ε rejections — the sparse-vector trick — hides that.

A second noisy number protects the abort: the filter stops early if failures reach a noisy cap K̃ = ceil(2σ₁L + Lap(σ₁)) with L = ln(16/δ), and returns all nulls ⊥ⁿ. The cap's noise hides whether the exceptional record caused one extra rejection. Together, both noises make the filter jointly private.

To be jointly private the filter needs enough blocks, but only linearly many in the block size:

$$m \ge 400\,L^{2}/\varepsilon^{3/2},\quad \sigma_m = 108L/\varepsilon^{3/2},\ \sigma_1 = 12/\varepsilon$$

so n = Ω(b·L²/ε^{3/2}). A naive analysis that paid for all n tests would need n = Ω(b²·L²/ε²) — quadratic. At ε=1, δ=10⁻⁶ this bound is about 110,000 blocks; the paper stresses the constants aren't tuned, only the order L²/ε^{3/2} matters.

Why test at 2τ to get τ? This is concavity. A score is concave if the score on a combined dataset is at least the size-weighted average of the scores on its parts. If your record is 2τ-friendly with more than 7m/8 blocks (after noise), and fewer than O(L/ε) records failed in total, at least ν ≥ m/2 intact 2τ-friendly blocks remain — discounting the failed blocks and your own. Their pooled data plus the rest (score ≥0) gives:
$$\varphi(\text{filtered without } i, s_i) \ge (\nu/m)\cdot 2\tau \ge \tau$$
That is exactly what the friendly release needs. For retention of all good data the paper asks a bit more, m ≥ 1800 L ln(2n/β)/ε^{3/2}, to control noise of all n tests at once — then every record with c_i > 15m/16 is kept with probability 1-β, unless fewer than 12L/ε records are bad.

In the lab, pick typical vs outlier records. Watch each record's block votes c_i, the noisy threshold t, and the noisy cap K̃. See how an outlier low on votes gets nulled, a typical high on votes survives, and how having at least half the blocks friendly at 2τ is enough to guarantee τ on the pooled remainder.

006Lesson 6~10 min

Testing a one-number summary

A one-number summary sounds easy to make private. Take all your vectors, average their squared lengths, add a little regularizer, and publish it. Call that average $Q(s) = \frac{1}{|s|}\sum \lVert s_i\rVert^2$ and the target $g_\lambda(s)=\ln(\lambda+Q(s))$. Its log scale means we care about relative error: being off by a factor $e^{\pm 0.1}$ is 10%.

One person could still blow it up. If you clip every record to a public cap $C$ and add noise proportional to $C$, a single huge $\lVert x\rVert$ can move $Q$ arbitrarily unless $C$ is enormous — and then the noise is enormous for everyone.

Propose-Filter-Release replaces the public cap by a comparison to the data itself.

A score that dominates the change

Say a friendliness score $\varphi(s,x)$ measures how typical $x$ is for dataset $s$ — bigger means more typical, less influence. It dominates $g$ if removing $x$ can never change $g$ by more than

$$|g(s)-g(s^{i\to\bot})| \le \frac{1}{n\,\varphi(s^{i\to\bot},s_i)}$$

then on any pair the filter calls $F_\tau$-friendly — meaning $\varphi \ge \tau$ — the sensitivity is at most $1/(\tau n)$. Add Laplace or Gaussian noise of scale $1/(\tau n)$ or $\sigma/(\tau n)$ and the release is friendly-DP: private whenever the changed record fits the rest. This is Theorem 5.2, and it needs nothing about worst-case records.

The trace example

For the log-regularized trace the paper uses

$$g_\lambda(s)=\ln(\lambda+Q(s)),\qquad \varphi_{\mathrm{tr},\lambda}(s,x)=\frac{\lambda+Q(s)}{\lVert x\rVert^2}$$

with $\varphi=\infty$ for $x=0$ and $0$ for $\bot$. In words: compare the squared length of the candidate to the scale $\lambda+Q$ of the reference block. Because $\ln(1+y)\le y$,

$$|g_\lambda(s)-g_\lambda(s^{i\to\bot})| = \ln\!\left(1+\frac{\lVert x\rVert^2}{n(\lambda+Q(s^{i\to\bot}))}\right)\le \frac{1}{n\varphi_{\mathrm{tr},\lambda}(s^{i\to\bot},x)}$$

so it dominates. It is also concave — $\lambda+Q$ on a pooled dataset is the size-weighted average — so the many-blocks-to-one-dataset math from Lesson 5 applies. Testing at $2\tau$ against blocks gives $\tau$ on the filtered data.

Paper's instantiation: with $L=\ln(16/\delta)$, noise $Y = g_\lambda(\hat s)+\mathcal N(0,(4\sqrt{L}/(\tau\varepsilon n))^2)$ makes $\mathrm{PFR}^{\varepsilon,\delta}_b(M,\varphi_{\mathrm{tr},\lambda},\tau)$ $(\varepsilon,\delta)$-DP on every input (Theorem 5.4). No bound on $\lVert x\rVert$ is assumed.

What does that buy you? With probability at least $1-\beta$, $e^{Y}$ is within a factor $e^{\pm\xi}$ of $\lambda+Q(\hat s)$ where $\xi$ is about $\sqrt{L\ln(1/\beta)}/(\tau\varepsilon n)$ — the denominator is $n$, not the dimension. Filtered means nulled records count as $0$ but keep their slot, so the denominator stays $n$.

Retention is a separate step. If every original record satisfies $\lVert x\rVert^2 \le \kappa(\lambda+Q(s^*))$ for a public $\kappa$, then random blocks of $\tilde O(\kappa)$ records are representative, and with $\tau=1/(4\kappa)$ the filter keeps everything with high probability (Corollary D.3). Even if fewer than $12L/\varepsilon$ records are swapped for arbitrary outliers, it still keeps all the good ones, and each outlier that slips through satisfies $\lVert x\rVert^2 \le 4\kappa(\lambda+Q(\hat s))$ by concavity — so in log scale it moves the answer by at most $8\kappa/n$. Without the filter that move would be unbounded.

In the lab, set your public $\kappa$ and $\lambda$ and watch blocks vote. Typical records with $\lVert x\rVert^2\approx 1$ are friendly with all $m=8$ blocks; huge outliers fail most block tests and get nulled, and the log-error stays inside the $\xi$ band and the $8\kappa|I|/n$ bound. Try raising the outlier size to 50 and see the filtered estimate barely budge while the raw average explodes.

007Lesson 7~14 min

Sketching a cloud privately

We have a bouncer that can filter records, but what does the bouncer actually check for a high-dimensional cloud? This lesson tells that checking story — and why it finally removes the dimension from the bill.

The job is to find a hidden flat: the $k$-dimensional subspace spanned by the top $k$ eigenvectors of a covariance. Think of $d=1000$ directions in space, but the data really vary along only $k=10$ of them. For a centered Gaussian the non-private answer needs about $\tilde{O}(k/\alpha^2)$ samples to get projector error $\|\tilde{P}-P_k(\Sigma)\| \le \alpha$ — growing with $k$, not $d$.

Naively privatizing it fails because global sensitivity is maximal. One huge record orthogonal to the cloud can swing the empirical subspace by $90$ degrees, so noise scaled to that worst case grows like a polynomial in $d$ (a noisy $d\times d$ matrix).

Paper's fix: measure influence with regularized leverage. For a non-empty reference set $s$, let $\hat{\Sigma}_\lambda(s)=s^Ts/|s|+\lambda I_d$ — the second moment plus a public ridge $\lambda I$. Then define

$$ \mathcal{L}_\lambda(s,x)=x^T\hat{\Sigma}_\lambda(s)^{-1}x, \qquad \varphi_\lambda(s,x)=1/\mathcal{L}_\lambda(s,x) $$

$\mathcal{L}_\lambda$ is a squared Mahalanobis norm: small along directions where $s$ varies a lot, large across them. $\varphi_\lambda$ is its reciprocal — a higher score means smaller influence. Lemma 5.6 shows $\varphi_\lambda$ is concave, exactly what the filter needs.

The test $\varphi_\lambda(s,x)\ge 2\tau$ asks: is $x$ inside the ellipsoid $\{y: y^T\hat{\Sigma}_\lambda(s)^{-1}y \le 1/(2\tau)\}$? That ellipsoid is long where the block is long and thin where it is thin — it knows direction, not just distance. A point far along the subspace is still inside; a point just a little off near the origin sticks out. This is why block checks beat pairwise distance.

The release is random combinations, not a noisy matrix. A Gaussian sketch draws $r$ vectors $Z_j\sim \mathcal{N}(0,\hat{\Sigma}_\lambda(s))$, each equals $\frac{1}{\sqrt{n}}\sum w_i s_i + \mathcal{N}(0,\lambda I)$. Re-adding one record $x$ changes the covariance $A=\hat{\Sigma}_\lambda(s^{i\to\bot})$ to $A+xx^T/n$ — a rank-one bump. Its effect is $\omega=x^TA^{\dagger}x/n=\mathcal{L}_\lambda/n\le 1/(\tau n)$. Prop D.4 shows both Rényi divergences are $\le \vartheta\omega^2/(4(1-(\vartheta-1)\omega))$. With $r$ independent sketches they add, giving Theorem 5.8: with $L=\ln(16/\delta)$, if $m= n/b \ge 400L^2/\varepsilon^{3/2}$ and $n\ge 2(\sqrt{rL}+L)/(\tau\varepsilon)$, PFR with sketches is $(\varepsilon,\delta)$-DP on every input. $d$ only enters through $1/\tau$ and $r$.

Why can $1/\tau$ stay small while $d$ is huge? The paper's hard example — the geometric spectrum — has $k-\lceil\log_2 d\rceil$ eigenvalues equal to 1 then $2^{-j}$ tail, cutoff $a=2^{-\lceil\log_2 d\rceil}\in (1/(2d),1/d]$, ratio $\lambda_{k+1}/\lambda_k=1/2$ (so gap $a/2$ shrinks with $d$) and tail sum $\le a$. Non-privately it still needs only $\tilde{O}(k/\alpha^2)$. With ridge $\lambda=a/d$ the effective dimension $\mathrm{Tr}(\Sigma(\Sigma+\lambda I)^{-1})\le 2k$, so blocks of $\tilde{O}(k)$ records already contain every direction.

Theorem 5.9 then sets $\lambda=a/d$, $\tau=1/(C(k+\ln(n/\beta)))$, $r=\lceil C(k+\ln(1/\beta))/\alpha^2\rceil$, $b\ge C(k+\ln(n/\beta))$, $m\ge \max(400L^2/\varepsilon^{3/2},1800L\ln(8n/\beta)/\varepsilon^{3/2})$, $n\ge C(k+\ln(1/\beta))/\alpha^2$, and gets with probability $\ge1-\beta$: filter keeps everyone and $\|\tilde{P}-P_k(\Sigma)\|\le\alpha$. Together the sample size is $\tilde{O}(k/\varepsilon^{3/2}+k/\alpha^2+k^{3/2}/(\alpha\varepsilon))$ — no polynomial factor in $d$, while published bounds were $d^2k^2/(\alpha^2\varepsilon)$, $d/\varepsilon+d^{3/2}/(\alpha\varepsilon)$, etc. The price is $k>\log_2 d$, so fixed $k$ covers $d\le 2^{k-1}$.

008Lesson 8~12 min

The same trick works elsewhere

PFR's promise is: give me any friendly-DP release that is accurate when a record fits the rest, and I will make it fully private. The last lesson used that for a toy logarithm and for subspaces. Here you see the same wrapper with three very different scores — each adapts to its own unknown scale, without a public cap.

📊

Histograms: who's missing?

Each user brings counts $H=(H_1,\dots,H_d)$ over $d$ categories, with $H_1+\dots+H_d=T$. Average counts are $\bar H_j$, smoothed by a public $\lambda>0$: $\hat p_j=(\lambda+\bar H_j)/(T+d\lambda)$. Target is $g_{KL}(s)=D_{KL}(u\|\hat p)$, distance of pooled frequencies from uniform $u=(1/d,\dots,1/d)$. Large when some category is barely covered; $\lambda$ keeps it finite.

🔌

Graphs: how strong is a connection?

Vertices are public, edges are records $x_e=\sqrt{w_e}(\chi_u-\chi_{u'})$, Laplacian $\mathbf L_G=\sum x_ex_e^{\top}$. Effective resistance $R_{eff}(u,u')=(\chi_u-\chi_{u'})^{\top}\mathbf L_G^{\dagger}(\chi_u-\chi_{u'})$ is the voltage for 1 amp. Many parallel paths = small resistance. Leverage $\ell_e=w_e\cdot R_{eff}(e)$ is the edge's share, at most 1 (a bridge has $\ell=1$).

💊

Treatment rules: which rule helps?

Each person has weight $w=y/\pi(a|z)$ — outcome divided by assignment chance. Risk $R_h(s)=W(s)^{-1}\sum w_i\cdot\mathbf 1\{h(z_i)\neq a_i\}$ is weighted error; smaller = more welfare. Weights are unbounded, no absolute cap is known.

Three scores, one shape

For histograms the score is $\varphi_{KL}(s,H)=\left(\frac1d\sum_{j=1}^d \frac{H_j}{\lambda+\bar H_j(s)}\right)^{-1}$ — the reciprocal of the average relative contribution. It weighs every category by its own average, so a user concentrated on a rare category is not punished for that alone. It can be written as an infimum of linear functions (Cauchy–Schwarz), hence concave, and it dominates the KL change: $|g_{KL}(s)-g_{KL}(s^{i\to\bot})|\le 1/(n\varphi_{KL})$.

For graphs the score is $\varphi_0(s,x)=1/\mathcal L_0(s,x)$ — reciprocal leverage, $\mathcal L_0=|s|\cdot x^{\top}\mathbf L_s^{\dagger}x$ (infinite if $x$ bridges disconnected parts). Also concave. The release draws Gaussian potentials $Y_j\sim\mathcal N(0,\mathbf L_{\hat s}^{\dagger})$; then $\hat R_{eff}(u,u')=r^{-1}\sum_j (Y_j(u)-Y_j(u'))^2$ has expectation $R_{eff}$. Same Rényi math as sketches, after swapping $C\leftrightarrow C^{-1}$, gives privacy.

For treatment the score is $\varphi_w(s,x)=W(s)/(|s|\,w(x))$ — average weight divided by this person's weight. Trivially concave (average of totals). The release is the exponential mechanism picking $h$ with probability $\propto \exp(-\varepsilon\tau n\,R_h/4)$, which is friendly-DP because on a friendly pair every $R_h$ moves at most $1/(\tau n)$.

When does the filter keep everyone?

Each paper theorem adds a retention condition that depends only on the data shape, not on privacy noise:

  • Histograms: if $H_{ij}\le \kappa(\lambda+\bar H_j(s))$ for every user $i$ and category $j$, then blocks of $\tilde O(\kappa)$ users are representative. With $\tau=1/(4\kappa)$ the filter keeps all, and $n=\tilde O(\kappa/\varepsilon^{3/2}+\kappa/(\alpha\varepsilon))$ users give error $\alpha$. Global-sensitivity Laplace would need $T/(d\lambda)$ times more — huge when $\lambda$ is tiny.
  • Graphs: if max leverage $\ell_{\max}$ is small and $m(v-1)\exp(-1/(8m\ell_{\max}))\le\beta_B$, the filter keeps all. Then relative error $\alpha$ needs roughly $\alpha\gtrsim \ell_{\max}/\varepsilon$ (up to logs), which is optimal — a matching lower bound deletes $1/\varepsilon$ edges at one vertex of a clique. Two cliques joined by a perfect matching have spectral gap $2$ but $\ell_{\max}\sim 1/v$, so PFR gives $O(1/(\varepsilon v))$ relative error where additive spectral bounds say nothing.
  • Treatment: if $w\le \kappa\mathbb E[w]$, blocks $\tilde O(\kappa)$ keep all with $\tau=1/(4\kappa)$. On kept data excess risk $\le (4/(\tau\varepsilon n))\ln(N/\beta)$; on original data it is at most $(1-\varrho)$ times that plus $\varrho$, where $\varrho$ is the fraction of total weight removed. So a few huge outcomes are fine if they respect the ratio.
Same structure each time: a concave score turns "friendly with many blocks at $2\tau$" into "friendly with all kept data at $\tau$"; Laplace noise $2/(\tau n\varepsilon)$ (or the Gaussian version) then gives friendly-DP, and Theorem 4.6 turns it into $(\varepsilon,\delta)$-DP on every input.

Beating worst-case lower bounds — for typical data

Here's the punchline of the whole paper, and its boundary. On the geometric spectrum from Lesson 7 — where the ratio of the last kept eigenvalue to the first dropped one is just 1/2 and the gap shrinks as 1/d — every published private guarantee the authors compare with needs a number of samples that grows like a power of the dimension d.

For example, the model-aggregation guarantee of [51] needs on the order of $d^2 k^2/(\alpha^2 \varepsilon)$ samples, the relative-covariance guarantee of [10] needs $\tilde O(d/\alpha^2 + d/\varepsilon + d^{3/2}/(\alpha \varepsilon))$, the Gaussian-perturbation bound of [41] grows like $d^{3/2}$, and block-block FriendlyCore still carries polynomial-in-$d$ terms at this ratio. That's the minimax price: protect the worst possible dataset, pay for $d$.

PFR breaks that barrier — not for every dataset, but for typical ones. Its privacy holds on every input under a public condition that only involves $\varepsilon$, $\delta$ and the block layout: with $L = \ln(16/\delta)$, needing $m \ge 400 L^2/\varepsilon^{3/2}$ blocks for privacy, and $m \ge 1800 L \ln(2n/\beta)/\varepsilon^{3/2}$ for retention, with threshold $t=7m/8$. At $\varepsilon=1$, $\delta=10^{-6}$ that's about $110{,}000$ blocks — the paper stresses that the constants were not optimized, only the order $L^2/\varepsilon^{3/2}$ matters.

On that geometric spectrum, when blocks of $\tilde O(k)$ records are representative, PFR needs
$$n = \tilde O\!\left(k/\varepsilon^{3/2} + k/\alpha^2 + k^{3/2}/(\alpha \varepsilon)\right)$$ with no explicit $d$ factor — a flat line as $d$ grows — versus polynomial-in-$d$ for the prior bounds. This holds for rank $k > \lceil \log_2 d \rceil$, so for fixed $k$ it covers dimensions up to $2^{k-1}$; for larger $d$ the rank must grow like $\log d$.

The trick is the separation: bad inputs (with many unfriendly records) are filtered or cause an abort that still returns $M(\bot^n)$ without signaling failure — so privacy never breaks — while typical inputs sail through with only $O(L/\varepsilon)$ rejections allowed and pay noise calibrated to their typical sensitivity $1/(\tau n)$, not the global worst case. The filtering cost is linear in block size $b$, $n = \Omega(b L^2/\varepsilon^{3/2})$, and adds to the release cost as a maximum, not a product.

Where it stops. The filter tolerates $O(L/\varepsilon)$ outliers, not a constant fraction of contamination. Thresholds, ridge $\lambda$, block size $b$, and any spectral info to set them are public and must be chosen without looking at the data. The filter evaluates the score $n \times m$ times. And it needs a small effective dimension $\mathrm{Tr}\,\Sigma(\Sigma+\lambda I)^{-1}=O(k)$ after adding the ridge — with a power-law eigenvalue tail $i^{-p}$ and $\lambda \sim 1/d$ the effective dimension stays $\Omega(d^{1/p})$, so small blocks stop being representative. An adaptation of [10] with a fixed public ridge may achieve the same guarantee, but that's not a published theorem; open questions include Gaussian tests to cut $m$, tolerating more outliers usefully, and privately choosing parameters.

ABCWord bank

Word bank.

Differential Privacy (DP)

Idea that changing one person's record should barely change what anyone seeing the output can guess. Formally, on neighbors s ≃ s′ (same slots, one slot nulled), the output distributions are (ε,δ)-indistinguishable: Pr[M(s)∈O] ≤ e^ε Pr[M(s′)∈O] + δ and vice versa.

Global sensitivity

The biggest possible change in a statistic when you change one record, over ANY two neighboring datasets. Noise scaled to this protects everyone but is often huge.

Local sensitivity

The biggest change when you change one record starting from YOUR dataset s. Can be tiny on typical data, but using it directly leaks information because the scale itself reveals s.

Down sensitivity

Paper's name for change when you only delete a record that is present. Friendly-DP release only needs to bound this for "friendly" records, not all records.

Zero-out adjacency

In this paper: null a record but keep its slot, so datasets keep same number of slots n (and same number of blocks m=n/b). Replacement = two zero-out steps via ⊥.

Joint DP (JDP)

"Filter is private if, after you null the changed slot i in both outputs, the two filtered datasets look indistinguishable." Formally F(s)^{i→⊥} ≈_{ε,δ} F(s^{i→⊥}). Filter may reveal whether it kept xi, but not much else.

Friendly DP

M is friendly-DP for predicate F if M(s^{i→⊥}) ≈ M(s) whenever F(s^{i→⊥}, si)=1. Privacy only required when the changed record fits the rest. Atypical outliers are handled by the filter first.

Friendliness score

Function φ(s,x) ≥0 scoring how typical record x is for dataset s. Higher = more typical / less influence. Threshold τ gives predicate Fτ: s is τ-friendly with x if φ(s,x) ≥ τ. Strict test in filter uses 2τ.

Concave score

φ((s,s′),x) ≥ (|s|·φ(s,x)+|s′|·φ(s′,x))/(|s|+|s′|). Score on pooled data is at least the size-weighted average. This lets PFR combine "friendly with many blocks" into "friendly with all filtered data" — e.g., (1/2)·2τ = τ.

Sparse Vector Technique (SVT)

Technique to answer many 0/1 threshold questions paying privacy cost only for the ~K "failures" (here rejections), not for all n queries. Paper uses fixed public threshold t + fresh Laplace noise per query, plus noisy cap K̃ = ceil(2σ1 L + Lap(σ1)). Needed because changing one record changes one block by ≤1 but changes one query arbitrarily.

Leverage

Measure of how much a vector x would stretch if you tried to build it from dataset s. With regularizer λ≥0: Lλ(s,x)= xᵀ Σ̂λ(s)⁻¹ x where Σ̂λ(s)= sᵀs/|s| + λI. Score φλ=1/Lλ is concave. Test is "x inside block's ellipsoid" (wide where data vary).

Gaussian sketch

Release that outputs r random combinations of the retained records: each sketch ~ N(0, Σ̂λ(s)). Its covariance change when re-adding x is controlled by leverage ω= Lλ(s^{i→⊥},x)/n ≤1/(τ n). Privacy follows from Rényi divergence bound ϑω²/(4(1−(ϑ−1)ω)).

L

ln(16/δ) in this paper. Appears everywhere the allowable failure δ enters: cap offset 2σ1 L, noise scales, block count. Smaller δ → larger L → more blocks needed.
