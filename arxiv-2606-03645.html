001Lesson 1~7 min

Why smart AIs fail simple sums

Large language models can solve hard word problems from GSM8K and MATH, yet they flub a plain sum like

$$651507672825 + 369229089834 + 294552136401 = 1315288899060$$

The model in the paper gets the first digits right, 131528..., then writes 9 instead of 8. Not random garbage — off by exactly 1.

This lesson is about that off-by-one mystery, on the exact task the paper studies.

The task, in three numbers per column

Take n = 3 integers, each with m = 10 digits. The paper built N = 10,000 random problems like 123 + 392 + 136. The model must generate the sum digit-by-digit, from the most significant digit (leftmost) to the least. Call the generation step p = 0,1,2,...

For each column p, look at the stack:

  • raw sum rp: just add the digits in that column, ignoring any carry. With 3 addends, rp is 0 to 27. Example: column with 3,9,5 → r = 17.
  • input carry cp: what spills over from the column to the right. For 3-term addition cp is 0, 1, or 2 (for 4-term it's 0 to 3).
  • answer digit sp: what you actually write:
$$s_p = (r_p + c_p) \bmod 10$$

That is: add raw sum and carry, keep the last digit, pass the rest on. The carry to the next left column is floor((rp+cp)/10).

Key idea: every answer digit is just rp + cp. Get either wrong by 1 and the output digit is off by 1.

What the paper found

Not all positions fail equally. Early and final positions have special behavior, but interior positions — especially p = 4 (the 5th digit generated, the paper's main window) — show a clear pattern.

At p = 4, 93.19% of the errors are +/-1. Not a random wrong digit, not a missing digit — a neighbor. That hints the mistake is not that the model forgot how to add, but that it hesitated on the carry.

The paper's goal is to explain why that hesitation happens by opening the model and looking at its internal map, rather than just counting wrong answers.

Try it yourself

002Lesson 2~8 min

How to read a model's thoughts

Imagine the model writing an answer one digit at a time, left to right. At step $p$ it must choose: “what is the next digit?” Right before it picks, its internal state is a long list of 2,560 numbers — the hidden vector $h_p^{(L)}$.

Think of $h$ as a current thought. $p$ is the position. The paper studies $p=4$ (the 5th digit the model writes out of 11). $L$ is the layer — Qwen3-4B has 36 layers, and layer 36 is the final thought after the last normalization, just before the model converts thought into a token. You can't picture 2,560 dimensions, but you can picture it as a point in space.

How do we read that point? With a probe. A probe is a tiny decoder you train separately. You show it thousands of examples: “here was $h_p^{(L)}$, and the true raw sum $r_p$ was 11, the true carry $c_p$ was 1, the correct digit $s_p$ was 2, and the model guessed $\hat{s}_p = 3$.” The probe learns a simple rule — like logistic regression or a small MLP — to guess one fact from $h$ alone. It never changes the big model; it just listens in.

The authors train several different probes on the same $h_p^{(L)}$: one for the ground-truth digit $s_p$, one for the model's own output $\hat{s}_p$, one for the raw column sum $r_p$, one for the input carry $c_p$, one for whether the model will be correct, and later even a continuous “pressure to carry” $\Phi_p$.

The surprise: the same single vector can be decoded both as “what is correct” and as “what the model will wrongly say.” When the model fails, the correct answer is still faintly present inside $h$. The paper calls this probe versatility — one point, many readable signals.

How can “2” and “3” live in the same thought? That suggests $h$ is not a single label but a location on a structured landscape, with different probes reading different directions.

The paper also tracks when this landscape forms. In early layers probes are near random guessing. Around layer 24 there is a sudden jump to over 90% for all the arithmetic probes. A separate “readout” that aligns the thought with actual vocabulary tokens only happens after layer 30. In short: the model first builds an organized arithmetic thought, then translates it into a digit.

In the lab below, be the probe yourself. Pick what you want to read from the same cloud of hidden points and slide through layers from messy to organized. Watch how accuracy moves — the dots never move when you switch targets, only their coloring does. That's versatility in action.

003Lesson 3~9 min

A map of arithmetic thoughts

Think of the model's hidden vector h as a location on a secret map. The paper takes thousands of those locations — one for each addition problem at the same step p=4 — and flattens them from 2560 dimensions down to 2 so we can look at them. Each dot is one thought about the next digit.

To make that flattening, the authors use UMAP with cosine distance (angle between vectors, not length) and the settings n_neighbors=300, min_dist=0.3. They also drop in the model's own digit embeddings — the vectors for "0" through "9" — as fixed landmarks called Anchors. If a dot sits near Anchor 3, the model is leaning to output 3 next.

The big picture: 10 digit basins

At zoomed-out scale the map looks like a backbone of 10 islands in order 0 → 9. Inside each island, correct predictions (blue in the paper's Figure 2) huddle at the center, near their Anchor. Errors (red) live on the beach between islands, already drifting toward the neighbor's Anchor. That closeness is why the most common mistake is off-by-one, not a random digit.

Key insight: numerical neighbors are geometric neighbors. If the thought drifts a little, it lands on the next digit.

Zoom in: 3 fibers inside every basin

Pick one island, say Anchor 1. It is not a solid blob. It splits into 3 parallel stripes — fibers — one for each possible incoming carry c. For 3-number addition, c can only be 0, 1, or 2. So "answer is 1 with no carry" lives on a different stripe than "answer is 1 but a 1 was carried in," even though both would print 1.

In simplified form, inside one basin the model keeps these layered:

  • c=0 fiber: e.g., state (s=1, hat s=1, c=0)
  • c=1 fiber: e.g., (s=1, hat s=1, c=1)
  • c=2 fiber: e.g., (s=1, hat s=1, c=2)

That two-level design — global backbone by digit, local texture by carry — repeats in every basin from 0 to 9. The paper checks it on Qwen3-4B (N=10,000 ten-digit problems) and the same pattern is there at other positions too.

Why this map, not a simpler one?

The authors could have used PCA, the straight-line method you might learn first. It failed. PCA's trustworthiness — a score for "do close points stay close after flattening?" — was only 0.863 and its first two directions explained only about 18% of the variation. In other words, the arithmetic thoughts live on a curved sheet, not a flat plane.

Non-linear maps did work: UMAP scored 0.995 and t-SNE scored 0.990. The paper keeps UMAP because it preserves both the tight fibers and the long chain of islands. That's why we can trust that the fibers are real, not an artifact of the projection.

Gently deeper: trustworthiness with n_neighbors=50 asks, for each dot, how many of its 50 nearest neighbors in 2560-D are still among its 50 nearest in 2-D. High means local neighborhoods survived the squish.

Next, explore it yourself: switch the coloring to see the same dots reorganize by digit vs by carry, and drag the detail slider to watch the backbone sharpen as n_neighbors grows — just as the paper shows moving from grainy to crisp.

Lab · 03
Basins and Fibers
Next: Threads of Raw Sum →
004Lesson 4~9 min

The secret tunnels between digits

Think of the model's thought-space as a map with ten valleys, one for each digit 0 to 9. We call each valley a digit basin — it's centered on a fixed point called an Anchor, which is just the model's built-in idea of what "7" means. Most of the time the hidden thought $\boldsymbol{h}_p^{(L)}$ sits near the middle of the correct valley.

But what's inside a valley? Look closer and each valley is striped. For 3-number addition the incoming carry $c_p$ — the 0, 1, or 2 you carry from the right — splits the valley into three thin fibers. Same digit, different history. A "2 that came from no carry" lives on a different fiber than a "2 that came from carry-1."

So what connects valleys to each other? Not a jump — a tunnel.

An Iso-Raw-Sum Trajectory (IRST) $\mathcal{T}_r$ is the set of all states that share the same raw sum $r$.
Raw sum is the column sum before you add the carry: $r_p = a_{0,p}+a_{1,p}+\dots$. For 3 terms it runs 0 to 27, but its last digit $r_p \bmod 10$ is what matters.
On one tunnel $\mathcal{T}_r$, the raw sum stays fixed. The only thing that moves you is the carry $\hat{c}_p$, via the rule $$\hat{s}_p = (r_p + \hat{c}_p) \bmod 10.$$ So $\mathcal{T}_r$ threads through neighboring valleys as carry ticks up.

A concrete thread makes it clear. Take $\mathcal{T}_1$ where $r=1$. When carry is 0, you need digit 1: $(s,\hat{s},c,\hat{c})=(1,1,0,0)$ in valley 1. Add one carry, you slide to valley 2: $(2,2,1,1)$. Add another, valley 3: $(3,3,2,2)$. In notation:

$$\mathcal{T}_1: (1,1,0,0) \leftrightarrow (2,2,1,1) \leftrightarrow (3,3,2,2)$$

Same $r=1$ the whole way. Same idea holds for every $r$. Globally you get ten parallel threads $\mathcal{T}_0\dots\mathcal{T}_9$ weaving back and forth through the ten valleys. In 3-number addition each valley has 3 fibers and each border between valleys $k \leftrightarrow k+1$ is crossed by 2 different threads.

Make the job harder — add four numbers — and $c_p$ can be 0,1,2,3. Now each valley has 4 fibers and each border is crossed by three threads. In a flat 2-D map they look tangled and overlapping, but lift them into 3-D and they separate again. The tunnel is still there; the map just got crowded. That crowding is why mistakes rise with more addends.

In the lab below, pick a tunnel $r$ and drag the carry $c$ slider. Watch the red dot travel along $\mathcal{T}_r$: raw sum never changes, the digit does only when carry clicks by 1. Toggle to 4-term mode to see why three bridges make the map tangle, and flip to 3-D to untangle it.

005Lesson 5~10 min

How close is close enough to carry?

Imagine every column of an addition has a kind of pressure building up from the right. The paper calls it Carry Potential, written Φ (say "phi"). It is not the carry itself — it is the continuous push toward a carry.

For a position p, look at all the raw sums to its right, r_{p+1}, r_{p+2}, .... A raw sum is just the column total before carrying, like 3+9+2 = 14. The potential weights them by place value:

$$\Phi_p = \sum_{j=1}^{P-1-p} \frac{r_{p+j}}{10^{j}}$$

So the column immediately to the right counts at full weight divided by 10, the next one divided by 100, and so on. The discrete carry you actually need is simply the whole-number part: c_p = floor(Φ_p), meaning round down. In the paper's example, the right-side context gives Φ = 1.4 + 0.11 = 1.51, so c = floor(1.51) = 1. A Φ of 0.73 means no carry, 1.05 means one carry, 2.49 means two carries, even though the model never sees those numbers written down.

Here is the key hypothesis. The model tries to estimate that pressure, but its estimate is a little noisy, like hearing a number through static:

$$\hat{\Phi}_p = \Phi_p + \epsilon,\quad \epsilon \sim \mathcal{N}(0,\sigma^2)$$

ε is tiny random jitter with average 0 and spread σ (sigma). The model then takes the floor: ĉ = floor(hat Φ). If Φ is 1.51 and σ is small, almost all noisy guesses still land between 1 and 2, so the floor stays 1. But if Φ is 1.98, half the jitter pushes it over 2.00 and the floor flips to 2.

The exact risk. Let δ = Φ mod 1 be the fractional part — how far past the last integer you are. Distance to the integer below is δ, to the one above is 1-δ. With Gaussian noise, the paper shows: $$P(\text{Error}|\Phi) = Q\!\left(\frac{\delta}{\sigma}\right) + Q\!\left(\frac{1-\delta}{\sigma}\right)$$ where Q(z) is just the tail chance that a bell curve exceeds z. Near an integer one term is huge; near .5 both are tiny.

That formula predicts a periodic bathtub: error spikes at integer thresholds 1.0, 2.0, … and valleys near half-integers 0.5, 1.5, 2.5. The paper's data matches with R² = 0.80 for 3-number addition, fitting σ ≈ 0.05. For harder tasks the noise grows: σ ≈ 0.12 for 4 numbers and σ ≈ 0.25 for 5 numbers, so the valleys get shallower and the bathtub flattens.

The Carry Pressure Meter

006Lesson 6~9 min

Mistakes as slides, not jumps

Last lesson you saw the hidden tunnels — the IRSTs — that thread through digit basins on a single raw sum. Now the question is: what's a mistake look like on that map?

The paper's answer: not a jump to a random place, but a slide along the same tunnel into the next basin.

Two kinds of slides

Pick a concrete tunnel, T1 where raw sum rp=1. It connects three calm parking spots:

$$\mathcal{T}_{1}: (1,1,0,0) \leftrightarrow (2,2,1,1) \leftrightarrow (3,3,2,2)$$

Read each tuple as (true digit, predicted digit, true carry c, predicted carry ĉc). In the middle spot the math really is s=(r+c)\bmod10 = (1+1)\bmod10=2 and the model predicts 2 too. All good.

A geometric slippage stays on T1 but slides off-target:

  • Hallucination: true state is (1,*,0,*) but model thinks ĉc=1. It outputs (1,2,0,1) — one basin too high.
  • Leakage: true state is (2,*,1,*) but model thinks ĉc=0. It outputs (2,1,1,0) — one basin too low.

Both are still (r+ĉc)\bmod10, just with ĉc = c±1. That is why 93% of errors at position p=4 are off-by-one — the tunnels only touch neighbors.

Key check: is this just a pretty UMAP picture? The team measured cosine distance to anchors directly in the real 2560-dimensional residual stream (ℝ2560). Distance vs. Carry Potential Φ still makes a clean V-shape across T0…T9. UMAP didn't invent the tunnels. And 0↔9 has no bridge — the backbone is helical, not a circle — so wrap-around errors like 0→9 are rare.

Carry-based vs. “I forgot the sum”

Are all errors slides? The authors used a raw-sum probe to split them.

If the probe still recovers the correct rp, the error is carry-based: the dot hugs the border between two basins on its Tr. If the probe gets rp wrong, the dot scatters far from any single tunnel — a different failure mode.

Most errors are the first kind. That supports Lesson 5's idea that Φ is the noisy variable: ĉc = floor(Φ̂) with Φ̂ = Φ+ε slips when Φ is near an integer (like 0.98 or 2.00).

Pushing proves cause

Correlation isn't cause, so the paper steered vectors. Between two stable centroids on one tunnel:

$$\vec{v}_{steer}=\frac{\boldsymbol{\mu}_{b}-\boldsymbol{\mu}_{a}}{\|\boldsymbol{\mu}_{b}-\boldsymbol{\mu}_{a}\|}$$

Each μ is the average hp(L) for a calm spot, like (4,4,1) and (5,5,2) on T3. Then they nudge any hidden state a little along that carry direction:

$$\tilde{\boldsymbol{h}}(\alpha)=\boldsymbol{h}+\alpha\cdot\vec{v}_{steer}$$

α>0 pushes toward the higher-carry basin, α<0 suppresses it. Result: metastable errors like (4,5,1; Φ=1.96) and (5,4,2; Φ=2.00) flip with |α|≈0.1–0.3, while stable spots like (4,4,1; Φ=1.62) and (5,5,2; Φ=2.36) need |α|≈0.5. Same direction, very different effort — exactly what you expect if Φ lives along vsteer and the boundary decides the digit.

007Lesson 7~8 min

One vector, many readable signals

A single hidden vector hp(L) at the last layer is 2,560 numbers — but the paper shows you can read many different facts from that one spot. Lightweight probes (tiny classifiers trained on hp(L) at position p=4, on balanced datasets) all work surprisingly well — yet some are much easier than others.

What probe readsSymbolAccuracy
Model's own next digitŝp98.81%
Raw sum mod 10rp mod 1098.60%
Input carrycp96.84%
Ground truth digitsp94.85%
Carry Potential (floored)⌊Φp⌋92.08%
Is the model correct?𝟙(ŝp≠sp)82.41%

This hierarchy is not about “more information” versus “less” — it is about what shape the probe must cut out of the manifold we saw in Lessons 3–4.

🎯

Easiest: ŝp

Just “which digit basin are you in?” The final layer is literally organized to pick the next token, so a probe only has to mimic the unembedding — a Voronoi line between Anchors. Even when the model is wrong, it is confidently in some basin.

🧵

Still easy: r mod 10

Which raw-sum thread Tr are you on? Remember, a slippage stays on the same thread while sliding to the neighbor basin. The color of the thread does not change when you slip, so it stays linearly separable.

〰️

Harder: correctness

Not “which basin” but “are you deep inside or on the fuzzy hillside between basins?” The IRST is continuous. There is no sharp “error flag” — only a smooth rise in risk near the boundary, so even the best line gets confused. That is why it drops to 82.41%.

Ground truth (94.85%) lags behind model output for the same reason: to recover sp on the ~14% of wrong cases, the probe must say “this point looks like Anchor 2, but label it 1.” That contradicts the local geometry the model already committed to.

Input carry (96.84%) is reading the thin fibers inside one basin — three parallel stripes for c=0,1,2. They are stratified, but packed tighter than whole basins, so a bit harder. Carry Potential Φ (92.08%) is hardest of the carry family: it asks for the continuous position along the thread, then floors it. Near thresholds like 1.0, a tiny noise flips ⌊Φ⌋, exactly the bathtub we saw in Lesson 5.

Why we know this is latent, not just echoing the output: Track the same probes across all 36 layers of Qwen3-4B. Accuracy for every arithmetic variable is near chance until layer 23, then jumps at layer 24 — the paper's “latent computation” phase. The Logit Lens (just applying the final unembedding matrix to earlier layers) stays blind until around layer 30, the “readout” phase. In layers 24–29 the IRST already exists in a subspace that is linearly separable but not yet rotated into vocab space. That gap proves the geometry is doing work, not just reflecting the token about to be emitted.

Why Probes Differ
Next: Fixing with Consistency →
008Lesson 8~9 min

Turning geometry into a fix

By now you know the model’s bug: its math map is continuous, but it must spit out a discrete digit. The paper asks — can we use the map itself to catch when it slips?

That’s the dual-stream check. From the single thought vector $h_p^{(L)}$ (the model’s hidden state for position $p$ at the last layer), you run two tiny probes you already met:

  • Local stream $\hat{r}_p$: a classifier that guesses the raw sum digit $r_p \bmod 10$ — the column addition without carry.
  • Global stream $\hat{\Phi}_p$: a regressor that guesses the continuous Carry Potential $\Phi_p$ — the pressure to carry from the right.

Both are cheap MLPs trained once and frozen. Together they should agree with what the model actually said, $\hat{s}_p$.

$$\hat{s}_p \stackrel{?}{\equiv} (\hat{r}_p + c) \pmod{10} \;\; \text{for some plausible } c$$

What counts as plausible? The paper turns $\hat{\Phi}_p$ into a little interval $[\hat{\Phi}_p-\delta, \hat{\Phi}_p+\delta]$ and collects every integer carry it touches:

$$\mathcal{K}_p(\delta)=\{\lfloor \phi \rfloor \mid \phi \in [\hat{\Phi}_p-\delta,\hat{\Phi}_p+\delta] \}$$

In plain words: $\delta$ is your noise margin. If $\delta=0$, you only allow $c=\lfloor\hat{\Phi}_p\rfloor$. If $\delta=0.1$, and $\hat{\Phi}_p=0.96$, your set is $\{0,1\}$ — you admit the carry is ambiguous right at the 1.0 threshold. You call the token consistent if at least one $c$ in $\mathcal{K}_p(\delta)$ makes the modular math work. If not, you intervene and project back onto the map:

$$s_{new} = (\hat{r}_p + \lfloor \hat{\Phi}_p \rfloor) \bmod 10$$
Why $\delta$ matters: $\delta\approx 0$ fixes the most errors but also overwrites good answers that sit legitimately near a boundary. $\delta\approx 0.1$ matches the paper’s measured noise $\sigma\approx 0.05$ — wide enough to forgive honest ambiguity, narrow enough to catch real slips.

On Qwen3-4B for 3-term 10-digit addition (10,000 problems, $p=4$), the numbers play out exactly like the bathtub from Lesson 5 predicts. Original token accuracy is 86.26%. With $\delta=0$ you climb to 87.27% and correct 44.39% of errors, but you only preserve 94.07% of originally correct tokens — too aggressive. With $\delta=0.1$ you get the paper’s best 89.56%, fixing 30.46% of errors while preserving 98.13% of correct ones. That beats steering (88.27%) and hard replacement (89.13%) and crushes re-prompting with “That step looks incorrect…” (79.90%). The peak of both token and question accuracy sits at $\delta\approx 0.12$ — the bottom of the bathtub.

An ablation nails the culprit. Give the checker the true carry and let it guess raw sum (R+TC): 96.0% accuracy. Give it the true raw sum and let it guess carry (TR+C): only 90.5%. Using both probes (R+C) is 86.7%. The local math is usually fine; the noisy carry is the bottleneck.

This isn’t one model’s quirk. Qwen3-8B on harder 12-digit addition and Gemma-3-4B-IT on 10-digit addition keep the same backbone of 10 digit basins and the same bathtub with $R^2\approx 0.7$ and $\sigma\approx 0.05$–0.07. For 4-term addition the map gets denser — three bridges between any two adjacent digits instead of two — so UMAP looks tangled in 2D but separates in 3D. And the paper checked specialized addition transformers too: under-converged they show the same continuous bridges; fully converged they snap to isolated basins.

In short: the model already knows the right pieces. The fix is just demanding internal consistency within the noise you measured.

Word bank.

LLM

, Large-scale AI that predicts next tokens. Here we study Qwen3-4B with 36 layers, thinking of it as doing 3-number addition of 10-digit numbers.

Residual stream / hidden state

The main information highway inside a Transformer. At each step p the vector h_p^(L) in R^2560 (final layer) holds what the model thinks the next digit should be.

Probe

A tiny classifier (like logistic regression) trained to read one fact from a hidden vector, without changing the LLM.

UMAP projection

A 2D map (UMAP) that keeps nearby points nearby so we can see high-dimensional geometry.

Raw sum

Column sum before carry: r_p = sum of input digits at position p. For three addends r_p is 0 to 27.

Input carry

The carry coming from the right: c_p is 0,1,2 for 3-term addition (0-3 for 4-term). Ground truth relation: s_p = (r_p + c_p) mod 10.

Digit basin / Anchor

Cluster in activation space centered near a digit's unembedding vector (0-9). The paper finds 10 basins forming the macroscopic backbone.

IRST

Iso-Raw-Sum Trajectory: the continuous fiber threading through adjacent basins that shares the same raw sum r. Example T1: (1,1,0,0) <-> (2,2,1,1) <-> (3,3,2,2) as carry grows.

Carry Potential Phi

Continuous carry pressure from the right context: Phi_p = sum_j r_{p+j} / 10^j. Then c_p = floor(Phi_p). Example from paper: 1.4+0.11=1.51 -> c=1.

Noisy Quantization Model

Paper's model: model perceives hat Phi = Phi + epsilon with epsilon ~ N(0, sigma^2) and outputs hat c = floor(hat Phi). Noise sigma ~0.05 for 3-term (0.12 for 4-term, 0.25 for 5-term).

Geometric slippage

The paper's name for an off-by-one error: the vector slides along its IRST across a digit boundary into the wrong basin.

Leakage vs Hallucination

Hallucination = hat c = c+1 (overestimates by 1). Leakage = hat c = c-1 (misses a carry). Both give hat s = s +/-1 mod 10.

Probe versatility

Why one vector can be probed for many things: different signals live in separable directions of the IRST geometry.

Bathtub curve

Error rate vs Phi is periodic bathtub: near 0.5,1.5 -> safe, near 1.0,2.0 -> spikes, predicted by Q(delta/sigma)+Q((1-delta)/sigma).
